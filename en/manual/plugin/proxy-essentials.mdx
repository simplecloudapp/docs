## Install the plugin

<Steps>
  <Step title="Install the plugin">
    Download Proxy Essentials from [GitHub](https://github.com/simplecloudapp/simplecloud-plugins/releases) or [Modrinth](https://modrinth.com/organization/simplecloud) and place the JAR in the proxy template's `plugins/` folder.
  </Step>

  <Step title="Start the proxy">
    Start a proxy. Proxy Essentials creates its files in `plugins/simplecloud-proxy-essentials/`.
  </Step>

  <Step title="Verify the plugin">
    Add the proxy to your Minecraft server list.

    <Check>
      The server list shows the SimpleCloud MOTD and icon.
    </Check>
  </Step>
</Steps>

To keep your changes, copy the `plugins/simplecloud-proxy-essentials/` folder into the proxy template. Files that only exist in a running group proxy are deleted when the proxy stops. See [Templates](/en/manual/setup/templates).

## Files

| File | Description |
| ---- | ----------- |
| `config.yml` | Join states, domains, whitelist, player count, tablist, and kick handling |
| `messages.yml` | Messages, date formats, and ping colors |
| `layout/*.yml` | Server list layouts with MOTD, icon, hover text, version, and slots |
| `layout/server-icons/` | Server icons used by the layouts |

## Join states

A join state decides who can join. You define join states in `config.yml` and set them on a group, a single server, or a persistent server.

```yaml config.yml
initial-state: public
initial-layout: public

joinstates:
  - name: public
    permission:
      join: ''
      full: 'simplecloud.proxy-essentials.join.full.public'
    forced-motd-layout: null
  - name: maintenance
    permission:
      join: 'simplecloud.proxy-essentials.join.maintenance'
      full: 'simplecloud.proxy-essentials.join.maintenance'
    forced-motd-layout: maintenance
```

| Setting | Description |
| ------- | ----------- |
| `name` | Name of the join state |
| `permission.join` | Permission needed to join. Leave it empty to allow everyone |
| `permission.full` | Permission needed to join when the proxy group is full |
| `forced-motd-layout` | Layout shown while this state is active on the proxy. `null` shows the normal layout |
| `initial-state` | Join state for targets that do not have one yet |
| `initial-layout` | Layout used when no other layout applies |

### Proxy and backend servers

Where you set a join state changes what it does:

| Target | Effect |
| ------ | ------ |
| Proxy group, such as `Proxy` | Controls who can join the network and can change the MOTD |
| Backend group, such as `Lobby` | Controls who can connect to the servers of this group |
| Single server, such as `Lobby-1` | Controls only this server |
| Persistent server, such as `Citybuild` | Controls only this persistent server |

<Info>
  Setting `Lobby` to maintenance does not change the MOTD. To put the whole network into maintenance, set the join state of the **proxy group**.
</Info>

### Activate maintenance

If your proxy group is called `Proxy`:

<Steps>
  <Step title="Set the join state">
    ```text
    /scproxy joinstate set group Proxy maintenance
    ```

    The join state is saved on the group and all its running servers. New servers of the group start with it as well.
  </Step>

  <Step title="Verify the join state">
    ```text
    /scproxy joinstate info group Proxy
    ```

    Players now need `simplecloud.proxy-essentials.join.maintenance` to join. Refresh your server list to see the maintenance MOTD.
  </Step>

  <Step title="Open the network again">
    ```text
    /scproxy joinstate set group Proxy public
    ```
  </Step>
</Steps>

More examples:

```text
/scproxy joinstate set group Lobby maintenance
/scproxy joinstate set group Lobby maintenance 1
/scproxy joinstate set ps Citybuild maintenance
```

The first command changes the whole `Lobby` group. The second changes only `Lobby-1`. The third changes the persistent server `Citybuild`.

### Servers outside SimpleCloud

Servers that SimpleCloud does not manage use `initial-state`. To give them another join state, add them by name:

```yaml config.yml
external-server-joinstates:
  queue-limbo: public
```

### Whitelist

Players on the whitelist can always join, even during maintenance or when the network is full.

```yaml config.yml
whitelist:
  enabled: true
  players:
    - Notch
    - 069a79f4-44e9-4726-a5be-fca90e38aaf5
```

You can use player names or UUIDs. Use the whitelist only for admins or emergency access. For everyone else, use permissions.

## Server list layouts

Each file in `layout/` is one layout. The file name is the layout name, so `layout/maintenance.yml` is the layout `maintenance`.

```yaml layout/public.yml
config-version: '2'

motd:
  enabled: true
  update-type: RANDOM # RANDOM or QUEUE
  # update-time: 100
  layouts:
    - name: public
      line1: '<center><color:#0ea5e9>A simplecloud.app network</center>'
      line2: ' '

server-icon:
  enabled: true
  file: simplecloud.png

player-list:
  enabled: true
  player-list:
    - ''
    - 'simplecloud.app'
    - ''

version:
  name:
    enabled: false
    text: Example
  slots:
    enabled: true
    type: REAL # REAL, FAKE, or DYNAMIC
    fake-slots: 100
    dynamic-player-range: 5
```

| Setting | Description |
| ------- | ----------- |
| `motd.layouts` | MOTD entries with two lines each |
| `motd.update-type` | `RANDOM` picks a random entry, `QUEUE` shows the entries in order |
| `motd.update-time` | Time in ticks until the next entry is shown. Without it, the entry changes on every ping. `0` always shows the first entry |
| `<center>` | Centers a line in the server list |
| `server-icon.file` | Icon from `layout/server-icons/` |
| `player-list` | Text shown when hovering over the player count |
| `version.name` | Text shown instead of the player count |
| `version.slots.type` | `REAL` shows the real max players, `FAKE` shows `fake-slots`, `DYNAMIC` shows online players plus `dynamic-player-range` |

### Which layout is shown

The proxy uses the first layout that exists:

1. The layout of a matching [domain](#motd-by-domain)
2. The `forced-motd-layout` of the proxy's active join state
3. The layout set with `/scproxy layout set`
4. `initial-layout`

To set a layout on a group, use:

```text
/scproxy layout set Proxy public
```

## MOTD by domain

Show a different layout depending on the domain players use, for example when several domains point to the same proxy.

```yaml config.yml
domains:
  - domain: play.example.com
    target: Lobby
    rules:
      - state: public
        layout: lobby-public
      - state: maintenance
        layout: lobby-maintenance

  - domain: citybuild.example.com
    target: Citybuild
    rules:
      - state: public
        layout: citybuild
```

| Setting | Description |
| ------- | ----------- |
| `domain` | Full domain, for example `play.example.com`. Wildcards are not supported |
| `target` | Group or persistent server whose join state picks the layout |
| `rules` | Layout for each join state of the target |

If no rule matches the target's join state, the proxy uses its `forced-motd-layout` and then `initial-layout`. If no domain matches, the normal [layout order](#which-layout-is-shown) applies.

<Info>
  This only changes the MOTD. To also send players of a domain to a specific server, use [subdomain routes](/en/manual/plugin/server-connection#subdomain-routes) of Server Connection.
</Info>

## Tablist

Tablist entries are in `config.yml`. The `name` is compared with the server the player is on.

```yaml config.yml
tablist:
  - name: Lobby
    layout:
      - header: '<green>Lobby'
        footer: '<gray>You are on <server_name>'
      - header: '<yellow>SimpleCloud'
        footer: '<gray><online_players> players online'
    update-time: 100

  - name: global
    layout:
      - header: '<color:#0ea5e9>SimpleCloud v3'
        footer: '<gray>Network'
    update-time: 20
```

The proxy uses the first entry that matches:

1. Exact server name, for example `Lobby-1`
2. Start of the server name, for example `Lobby` for `Lobby-1`
3. `*`
4. `global`

If an entry has several layouts, they rotate every `update-time` ticks. With `update-time: 0`, the first layout is always shown.

## Player count

The player count includes all proxies of the current proxy group. You can add more groups and persistent servers, or show all players of the network.

```yaml config.yml
player-count:
  enabled: true
  network: false
  additional-groups:
    - BedrockProxy
  additional-persistent-servers:
    - EventProxy
  update-time: 20
```

| Setting | Description |
| ------- | ----------- |
| `network` | `true` shows all online players of the network |
| `additional-groups` | Groups whose players are added |
| `additional-persistent-servers` | Persistent servers whose players are added |
| `update-time` | Update interval in ticks. `0` counts only once on startup |

<Note>
  Pings from the machine the proxy runs on show the real player count and no hover text. Test the player count from another machine.
</Note>

## Kick handling

```yaml config.yml
show-kick-reason: false
```

With `true`, a player who is kicked from a backend server is disconnected with the kick reason instead of being sent to a fallback server.

## Placeholders

| Placeholder | Where | Description |
| ----------- | ----- | ----------- |
| `<online_players>` | Everywhere | Online players |
| `<max_players>` | Everywhere | Max players of the selected slot type |
| `<date>` | Everywhere | Current date |
| `<time>` | Everywhere | Current time |
| `<date:'pattern'>` | Everywhere | Current date and time in your own format, for example `<date:'HH:mm'>` |
| `<env:NAME>` | Everywhere | Value of an environment variable |
| `<env:NAME:default>` | Everywhere | Value of an environment variable with a fallback |
| `<server_name>` | Tablist | Server the player is on |
| `<ping>` | Tablist | Ping of the player in the matching color |

<Warning>
  Do not show passwords, tokens, or other secrets with `<env:NAME>`. Everyone can see the MOTD.
</Warning>

You can change the date formats and ping colors in `messages.yml`.

All texts use [MiniMessage](https://docs.papermc.io/adventure/minimessage/). Legacy color codes like `&a` are not supported.

## Commands

| Command | Description |
| ------- | ----------- |
| `/scproxy` or `/scproxy help` | Show the commands you can use |
| `/scproxy reload` | Reload the plugin |
| `/scproxy joinstate help` | Show the join state commands |
| `/scproxy joinstate list` | List all join states from `config.yml` |
| `/scproxy joinstate info` | Show the join state of all groups and persistent servers |
| `/scproxy joinstate info <group\|ps> <target> [id]` | Show the join state of a group, server, or persistent server |
| `/scproxy joinstate set <group\|ps> <target> <joinstate> [id]` | Set the join state of a group, server, or persistent server |
| `/scproxy layout help` | Show the layout commands |
| `/scproxy layout info [group]` | Show the layout of a group, or `initial-layout` without a group |
| `/scproxy layout set <group> <layout>` | Set the layout of a group |

## Use other plugins

You do not have to use every feature. Turn off the ones another plugin handles:

| Feature | How to turn it off |
| ------- | ------------------ |
| MOTD | Set `motd.enabled: false` in every layout |
| Tablist | Set `tablist: []` in `config.yml` |
| Player count | Set `player-count.enabled: false` in `config.yml` |
| Join restrictions | Set every group back to a join state with an empty `permission.join`, for example `public` |

A MOTD plugin must run on the proxy, not on a lobby server.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The plugin or its files do not appear">
    Make sure Proxy Essentials and `simplecloud-api` are in the **proxy** template, not in a lobby template. Then restart the proxy and check the console.
  </Accordion>

  <Accordion title="Maintenance is active, but the MOTD does not change">
    Make sure you set the join state on the proxy group, not only on a backend group. Check that the `forced-motd-layout` exists in `layout/` and has `motd.enabled: true`.
  </Accordion>

  <Accordion title="A domain shows the normal MOTD">
    Check that the player uses exactly the domain from `domain`, that `target` is a group or persistent server, and that the layout in `rules` exists.
  </Accordion>

  <Accordion title="Nobody can join">
    Check the console. If a group uses a join state that does not exist in `config.yml`, nobody can join. Add the join state or set the group to an existing one.
  </Accordion>

  <Accordion title="Colors are shown as text">
    Replace legacy codes like `&a` with MiniMessage tags like `<green>`.
  </Accordion>
</AccordionGroup>
