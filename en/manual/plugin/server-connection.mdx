## Install the plugin

<Steps>
  <Step title="Install the plugin">
    Download Server Connection from [GitHub](https://github.com/simplecloudapp/simplecloud-plugins/releases) or [Modrinth](https://modrinth.com/organization/simplecloud) and place the JAR in the proxy template's `plugins/` folder.
  </Step>

  <Step title="Match your lobby servers">
    By default, players are sent to servers whose name starts with `lobby`. If your lobby group has another name, change the `lobby` connection in `config.yml`.
  </Step>

  <Step title="Verify the plugin">
    Start a proxy and join it. Then switch to another server and run `/lobby`.

    <Check>
      You join a lobby server, and `/lobby` sends you back to a lobby.
    </Check>
  </Step>
</Steps>

On the first start, Server Connection creates `config.yml`, `commands.yml`, and `messages.yml` in `plugins/simplecloud-connection/`. To keep your changes, copy this folder into the proxy template. See [Templates](/en/manual/setup/templates).

<Warning>
  With `registration.enabled: true`, Server Connection replaces the proxy's server list with your SimpleCloud servers. Add servers outside SimpleCloud to `registration.additional-servers`, or set `registration.enabled` to `false` if another plugin manages the server list.
</Warning>

## How it works

Everything is based on **connections**. A connection is a named set of servers, for example all servers starting with `lobby`. You use connections in four places:

| Place | Description |
| ----- | ----------- |
| `network-join-targets` | Where players go when they join the network |
| `fallback` | Where players go when their server stops or kicks them |
| `address.routes` | Where players go when they join with a specific domain |
| `commands.yml` | Where commands like `/lobby` send players |

Inside a connection, the player is sent to the server with the fewest players. Servers that are stopping are skipped.

## config.yml

```yaml config.yml
version: 2

registration:
  enabled: true
  server-name-pattern: '<group>-<numerical_id>'
  persistent-server-name-pattern: '<name>'
  ignore-server-groups-and-persistent-servers: []
  additional-servers: []

address:
  routes: []

connections:
  - name: lobby
    server-name-matcher:
      operation: STARTS_WITH
      value: lobby
      negate: false
    rules: []

network-join-targets:
  enabled: true
  target-connections:
    - name: lobby
      priority: 0

fallback:
  enabled: true
  target-connections:
    - name: lobby
      priority: 0
      from: []
```

### Server registration

| Setting | Description |
| ------- | ----------- |
| `enabled` | Registers SimpleCloud servers on the proxy |
| `server-name-pattern` | Name of group servers on the proxy. Placeholders: `<group>`, `<numerical_id>`, `<id>`, `<name>` |
| `persistent-server-name-pattern` | Name of persistent servers on the proxy |
| `ignore-server-groups-and-persistent-servers` | Groups and persistent servers that are not registered |
| `additional-servers` | Servers outside SimpleCloud |

You can also use server properties in the name patterns. A property like `display-name` becomes `<display_name>`.

```yaml config.yml
registration:
  additional-servers:
    - name: build
      address: 127.0.0.1
      port: 25565
```

### Connections

```yaml config.yml
connections:
  - name: lobby
    server-name-matcher:
      operation: STARTS_WITH
      value: lobby
      negate: false
    rules: []
```

| Operation | Matches if the server name | Example value |
| --------- | -------------------------- | ------------- |
| `STARTS_WITH` | Starts with the value | `lobby` |
| `ENDS_WITH` | Ends with the value | `-1` |
| `CONTAINS` | Contains the value | `hub` |
| `EQUALS` | Is exactly the value | `lobby-1` |
| `REGEX` | Fully matches a Java regex | `lobby-\d+` |
| `PATTERN` | Fully matches a Java regex, same as `REGEX` | `lobby-\d+` |
| `GREATER_THAN` | Is a number greater than the value | `5` |

`STARTS_WITH`, `ENDS_WITH`, `CONTAINS`, and `EQUALS` ignore upper and lower case. Set `negate: true` to invert the match, for example to match all servers that do **not** start with `lobby`.

### Rules

Rules decide if a player may use a connection. If a rule fails, the connection is skipped and the next one is tried.

**Permission rule**

```yaml config.yml
rules:
  - type: PERMISSION
    name: server.join.vip
    value: 'true'
    bypass-permission: rank.admin
```

With `value: 'true'`, the player needs the permission. With `value: 'false'`, the player must not have it.

**Environment variable rule**

```yaml config.yml
rules:
  - type: ENV
    name: SERVER_STATE
    value: maintenance
    operation: EQUALS
    negate: true
    bypass-permission: rank.admin
```

Compares an environment variable of the proxy with `value`. You can use every operation from the table above.

Players with the `bypass-permission` skip the rule. Rules apply everywhere: on join, on fallback, on subdomain routes, and on commands.

### Join and fallback

`network-join-targets` decides where players go when they join. `fallback` decides where they go when their server stops or kicks them.

```yaml config.yml
network-join-targets:
  enabled: true
  target-connections:
    - name: vip-lobby
      priority: 10
    - name: lobby
      priority: 0

fallback:
  enabled: true
  target-connections:
    - name: lobby
      priority: 0
      from: []
```

- The connection with the highest `priority` is tried first.
- If it has no available server, or a rule fails, the next connection is tried.
- `from` only uses the fallback if the player comes from one of these **connections**. Leave it empty to allow every server.
- If no server is found, the player is disconnected.

### Subdomain routes

Send players to a connection based on the domain they join with:

```yaml config.yml
address:
  routes:
    - subdomain: 'play.example.com'
      target-connection: lobby
    - subdomain: 'smp.example.com'
      target-connection: smp

connections:
  - name: lobby
    server-name-matcher:
      operation: STARTS_WITH
      value: lobby
      negate: false
    rules: []

  - name: smp
    server-name-matcher:
      operation: EQUALS
      value: smp
      negate: false
    rules: []
```

Players who join with `smp.example.com` go to the server `smp`. Everyone else uses `network-join-targets`.

- Use the full domain, for example `smp.example.com`. Wildcards like `*.example.com` are not supported.
- `target-connection` is the name of a connection, not of a server.
- If the route has no available server, or a rule fails, `network-join-targets` is used.
- Point every domain to your proxy with an `A`, `AAAA`, or `CNAME` record. If the proxy does not use port `25565`, also add an `SRV` record.

## commands.yml

Create commands that send players to a connection:

```yaml commands.yml
version: 2

commands:
  - name: lobby
    aliases:
      - l
      - hub
      - quit
      - leave
    permission: ''
    target-connections:
      - name: lobby
        priority: 0
        from: []
    messages:
      already-connected: '<color:#dc2626>You are already connected to this lobby!'
      no-target-connection-found: "<color:#dc2626>Couldn't find a target server!"
```

| Setting | Description |
| ------- | ----------- |
| `name` | Command name |
| `aliases` | Other names for the command |
| `permission` | Permission needed for the command. Leave it empty to allow everyone |
| `target-connections` | Connections the command sends players to, with `priority` and `from` like in `fallback` |
| `messages` | Message when the player is already on the target, or when no server is found |

## Troubleshooting

<AccordionGroup>
  <Accordion title="Players cannot join a server">
    Check that `network-join-targets.enabled` is `true` and that the connection matches at least one running server. By default, the name must start with `lobby`. The console warns you if a connection is used but not defined.
  </Accordion>

  <Accordion title="A server outside SimpleCloud is missing">
    Add it to `registration.additional-servers`.
  </Accordion>

  <Accordion title="A subdomain route does not work">
    Use the full domain in `subdomain`, point the domain to the proxy, and check that `target-connection` is an existing connection with a running server. Also check the rules of the connection.
  </Accordion>

  <Accordion title="Servers are missing after SimpleCloud restarts">
    Server Connection loads all servers again once SimpleCloud is back. If servers are still missing, check the proxy console.
  </Accordion>
</AccordionGroup>
