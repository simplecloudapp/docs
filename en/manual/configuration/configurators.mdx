## What configurators do

Configurators edit server software files during preparation. They set values such as ports, forwarding secrets, online mode, and player limits before the server process starts.

The serverhost loads configurators from `options/configurators/{name}.yml`. A group or persistent server selects the configurator through its blueprint settings.

## Configurator structure

Each configurator has a `paths` list. Every entry names a file, the file type, and the data that should be written or merged.

```yaml
# options/configurators/paper_velocity.yml
paths:
  - path: "server.properties"
    type: "PROPERTIES"
    data:
      server-ip: "0.0.0.0"
      server-port: %port%
      max-players: %max-players%
      online-mode: false

  - path: "config/paper-global.yml"
    type: "YML"
    data:
      proxies:
        velocity:
          enabled: "true"
          online-mode: "true"
          secret: "%forwarding-secret%"
```

## Supported file types

| Type | Use for |
| ---- | ------- |
| `YML` | YAML files such as `config.yml`, `spigot.yml`, or `paper-global.yml` |
| `PROPERTIES` | Java `.properties` files such as `server.properties` |
| `TOML` | TOML files such as `velocity.toml` |
| `JSON` | JSON configuration files |
| `TXT` | Plain text files such as `forwarding.secret` |

## Placeholders

Configurators use percent placeholders. The serverhost replaces them before it parses the YAML file.

| Placeholder | Description |
| ----------- | ----------- |
| `%port%` | Assigned server port |
| `%group%` | Group name |
| `%numerical-id%` | Numerical server ID inside the group |
| `%type%` | Server type |
| `%min-memory%` | Minimum memory in MB |
| `%max-memory%` | Maximum memory in MB |
| `%max-players%` | Maximum player count |
| `%forwarding-secret%` | Proxy forwarding secret |
| `%velocity-config-version%` | Velocity config version when available |

Server and blueprint properties can also be exposed as placeholders by the runtime. Keep custom property names stable so templates and configurators do not drift.

## Velocity example

```yaml
# options/configurators/velocity.yml
paths:
  - path: "velocity.toml"
    type: "TOML"
    data:
      bind: "0.0.0.0:%port%"
      show-max-players: %max-players%
      forwarding-secret-file: "forwarding.secret"
      player-info-forwarding-mode: "MODERN"

  - path: "forwarding.secret"
    type: "TXT"
    data: "%forwarding-secret%"
```

## Built-in configurators

| Configurator | Purpose |
| ------------ | ------- |
| `spigot` | Spigot or Paper behind a BungeeCord-style proxy |
| `spigot_standalone` | Standalone Spigot or Paper server |
| `paper_velocity` | Paper behind Velocity modern forwarding |
| `velocity` | Velocity proxy |
| `bungeecord` | BungeeCord proxy |
| `waterfall` | Waterfall proxy |
| `luckperms` | LuckPerms storage configuration template |

## Apply a configurator

The default setup action calls `configurate` with the configured blueprint value:

```yaml
- name: configurate-server
  uses: simplecloud/configurate
  with:
    configurator: "{{ runtime.configurator }}"
    dir: "{{ runtime.server-dir }}"
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Configuration is not applied">
    Check that the blueprint selects the expected configurator name and that `options/configurators/{name}.yml` exists on the serverhost.
  </Accordion>

  <Accordion title="A placeholder remains in the generated file">
    Use percent syntax such as `%port%`, not `{{port}}`. Also verify the runtime actually provides the placeholder you used.
  </Accordion>

  <Accordion title="The configurator fails to parse">
    Check that every entry has `path`, uppercase `type`, and `data`. The `type` must be one of `YML`, `PROPERTIES`, `TOML`, `JSON`, or `TXT`.
  </Accordion>
</AccordionGroup>
