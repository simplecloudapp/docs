## What workflows are

Workflows are YAML files that the serverhost runs while preparing or cleaning up a server. They copy template files, download configured plugins, apply configurators, manage cache files, and remove temporary runtime directories.

Workflow files live in `workflows/`. The workflow ID is the namespace and file name without `.yml`, such as `internal/setup` for `workflows/internal/setup.yml`.

## Default workflows

Every serverhost creates the default workflow files on first start:

| Workflow | Purpose |
| -------- | ------- |
| `internal/setup` | Prepares a server directory before the process starts |
| `internal/cleanup` | Copies cache/log data and removes temporary dynamic server directories |

Server groups and persistent servers store the workflows they run in their base configuration:

```yaml
workflows:
  when:
    start:
      - internal/setup
    stop:
      - internal/cleanup
```

The dashboard manages the common defaults for you. Edit workflow files directly only when you need custom file preparation, backup, upload, or cleanup behavior.

## Workflow structure

A workflow has a readable `name`, optional `variables`, and a `steps` list. Each step has a `name`, a `uses` action identifier, optional `if` and `async` settings, and action parameters under `with`.

```yaml
# workflows/default/backup.yml
name: Backup Workflow

steps:
  - name: copy-running-to-backup
    uses: simplecloud/copy
    with:
      from: "{{ runtime.server-dir }}"
      to: "{{ runtime.templates }}/.backup/{{ runtime.name }}/{{ time.now.date }}/{{ time.now.dateTime }}-{{ runtime.nice-id }}"
      init-dir-if-missing: true
```

Variables are useful when several steps share the same path or value:

```yaml
name: Archive World

variables:
  backup-dir: "{{ runtime.templates }}/.backup/{{ runtime.name }}/{{ time.now.date }}"

steps:
  - name: compress-world
    uses: simplecloud/compress
    with:
      from: "{{ runtime.server-dir }}/world"
      to: "{{ vars.backup-dir }}/world.zip"
```

## Runtime values

Workflow expressions use `{{ ... }}` syntax. The most useful values are:

| Value | Description |
| ----- | ----------- |
| `{{ runtime.name }}` | Group or persistent server name |
| `{{ runtime.nice-id }}` | Runtime server name, such as `lobby-1` |
| `{{ runtime.type }}` | Mapped server type, such as `server` or `proxy` |
| `{{ runtime.persistent }}` | Whether this is a persistent server |
| `{{ runtime.numerical-id }}` | Numerical ID for group servers |
| `{{ runtime.server-dir }}` | Directory of the server being prepared |
| `{{ runtime.templates }}` | Template root directory |
| `{{ runtime.port }}` | Assigned server port |
| `{{ runtime.software }}` | Server software from the blueprint |
| `{{ runtime.mapped-software }}` | Platform-mapped software name |
| `{{ runtime.minecraft-version }}` | Minecraft version from the blueprint |
| `{{ runtime.configurator }}` | Configurator selected by the blueprint |
| `{{ runtime.tags }}` | Tags assigned to the group or persistent server |
| `{{ runtime.properties.<key> }}` | Custom property from the base server configuration |
| `{{ vars.<key> }}` | Variable defined by the workflow or a `foreach` step |
| `{{ time.now.date }}` | Current local date, useful for backup folders |

## Common actions

### `simplecloud/copy`

Copies a file or directory.

```yaml
- name: copy-template
  uses: simplecloud/copy
  with:
    from: "{{ runtime.templates }}/{{ runtime.name }}"
    to: "{{ runtime.server-dir }}"
    init-dir-if-missing: true
    replace: false
```

| Field | Description |
| ----- | ----------- |
| `from` | Source file or directory |
| `to` | Destination file or directory |
| `replace` | Whether existing files are overwritten. Defaults to `true` |
| `init-dir-if-missing` | Creates a missing source directory and continues. Defaults to `false` |
| `exclude` | Optional path or list of paths/globs to skip |

### `simplecloud/delete`

Deletes a file or directory.

```yaml
- name: delete-running-dir
  uses: simplecloud/delete
  if: "{{ runtime.persistent }} == false"
  with:
    path: "{{ runtime.server-dir }}"
```

Optional fields include `force` and `min-age`, such as `10m`, `2h`, or `7d`.

### `simplecloud/foreach`

Runs nested steps for each item in a list.

```yaml
- name: copy-tagged
  uses: simplecloud/foreach
  with:
    items: "{{ runtime.tags }}"
    as: tag
    steps:
      - name: copy-tag-{{ vars.tag }}
        uses: simplecloud/copy
        with:
          from: "{{ runtime.templates }}/_tagged/{{ vars.tag }}"
          to: "{{ runtime.server-dir }}"
          replace: false
```

### `simplecloud/load-plugins`

Downloads configured plugins from Modrinth, Hangar, Spigot, or direct URLs, then copies them into the server plugin directory.

```yaml
- name: load-plugins
  uses: simplecloud/load-plugins
  with:
    minecraft-version: "{{ runtime.minecraft-version }}"
    platform: "{{ runtime.software }}"
    plugins-dir: "{{ runtime.server-dir }}/plugins"
    cache-dir: "{{ runtime.cache-dir }}"
    type: "{{ runtime.type }}"
```

### `simplecloud/configurate`

Applies a configurator from `options/configurators/`.

```yaml
- name: configurate-server
  uses: simplecloud/configurate
  with:
    configurator: "{{ runtime.configurator }}"
    dir: "{{ runtime.server-dir }}"
```

See [Configurators](/en/manual/configuration/configurators) for the configurator file format.

### Archives and uploads

Use `simplecloud/compress`, `simplecloud/decompress`, and `simplecloud/upload` for backups or external storage workflows.

```yaml
- name: compress-world
  uses: simplecloud/compress
  with:
    from: "{{ runtime.server-dir }}/world"
    to: "{{ runtime.templates }}/.backup/{{ runtime.name }}/world.zip"
```

```yaml
- name: upload-backup
  uses: simplecloud/upload
  with:
    from: "{{ runtime.templates }}/.backup/{{ runtime.name }}/world.zip"
    to: "https://example.com/backups/world.zip"
    method: PUT
```

## Conditions and async steps

Use `if` to skip a step unless a condition matches. Conditions support common comparisons, `&&`, `||`, `exists(...)`, `!exists(...)`, and `value(path, default)`.

```yaml
- name: copy-logs-to-archive
  uses: simplecloud/copy
  if: "{{ runtime.persistent }} == false"
  with:
    from: "{{ runtime.server-dir }}/logs/"
    to: "{{ runtime.templates }}/cache/logs/{{ runtime.name }}/{{ runtime.nice-id }}"
```

Set `async: true` only for independent steps. The workflow waits for async work before it reports success or failure.

## Troubleshooting

<AccordionGroup>
  <Accordion title="A workflow does not run">
    Check the server group or persistent server workflow list. The workflow ID must match the path under `workflows/`, for example `internal/setup`.
  </Accordion>

  <Accordion title="A workflow cannot be loaded">
    Make sure the YAML file has `name` and `steps`, and that each step has a `uses` action identifier.
  </Accordion>

  <Accordion title="A value is not replaced">
    Use `{{ runtime.name }}` or `{{ vars.name }}` syntax. Percent placeholders such as `%server-dir%` belong to configurators, not workflows.
  </Accordion>

  <Accordion title="Plugin or template files are missing">
    Check the relevant `simplecloud/copy` source path and whether `init-dir-if-missing` should be enabled for that folder.
  </Accordion>
</AccordionGroup>
