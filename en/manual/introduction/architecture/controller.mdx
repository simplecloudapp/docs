## From configuration to running servers

When you activate a group, change its scaling settings, or start a persistent server:

1. The controller works out which servers should be running.
2. It chooses an eligible serverhost with enough resources.
3. The serverhost prepares and runs the Minecraft server.
4. Its status, logs, and resource usage become available in the dashboard and CLI.

You use the dashboard or CLI to configure what should run. The controller tracks your server groups, persistent servers, and connected [serverhosts](/en/manual/introduction/architecture/serverhost).

It keeps the dashboard and CLI updated with their current state.

The controller continues to maintain the result you configured. For example, it can start another group server when players need more capacity, or replace a group server that you stopped while the group still requires it.

<Note>
  The controller coordinates Minecraft servers but does not run them. Your serverhosts provide the machines and resources on which they run.
</Note>

## What this means for you

You do not need to manage the controller separately during everyday use.

If a server cannot start, first check that an allowed serverhost is online and has enough free memory. Then open the server or serverhost logs to see whether preparation or the Minecraft process failed.
