## Version Checks

SimpleCloud components and the CLI can check whether newer releases are available. The CLI will prompt you when it is too far behind the latest release, so you know when an upgrade is required.

- Use `simplecloud upgrade cli` to update the CLI itself.
- Use `simplecloud upgrade` when you want the CLI to upgrade supported installed targets.
- Review component restarts before upgrading production hosts.
- Keep configuration and template backups before changing runtime components.

<Note>
  The CLI prompts you to update when it is more than 5 versions behind the latest release.
</Note>

## Operational Impact

Updates can restart SimpleCloud components. Plan them like any other infrastructure change:

- Update one serverhost first when possible.
- Confirm server startup and shutdown still work.
- Roll the same update to the remaining hosts.
- Watch dashboard status and serverhost logs during the rollout.

## Manual Updates

If you prefer to trigger updates manually, use the upgrade command:

```bash
simplecloud upgrade
```

With no targets, this upgrades the CLI and all installed components. You can also upgrade specific targets:

```bash
simplecloud upgrade [targets..]
```

Targets can be `cli`, component IDs, or component version pins such as `serverhost@1.2.3`.

<Note>
  `simplecloud update` still works as an alias for `simplecloud upgrade`.
</Note>

## Updating the CLI

The CLI itself can be updated separately using:

```bash
simplecloud upgrade cli
```

This command checks for a newer CLI version, downloads it, and replaces your current installation. Use `simplecloud upgrade cli --cli-force` to reinstall the latest CLI even when it is already current.
