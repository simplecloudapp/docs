title: 'Persistent Servers'
description: 'Create single server instances that keep their identity and data across restarts.'
---

<Info>
  Need SimpleCloud to create multiple interchangeable servers based on player demand? Use [Server Groups](/en/manual/setup/server-groups) instead.
</Info>

## When to use a persistent server

| Use a persistent server when... | Use a group when... |
| ------------------------------- | ------------------- |
| The server has long-lived world data | Servers can be recreated from a shared template |
| You want one named server, such as `survival` | You want multiple instances, such as `lobby-1`, `lobby-2` |
| You choose the serverhost during setup | SimpleCloud should distribute servers across hosts |
| You want manual, predictable capacity | You want automatic scaling |

## Create a persistent server

<Steps>
  <Step title="Open the server wizard">
    In the dashboard, open **Persistent Servers** and click **Add Server**.
  </Step>

  <Step title="Choose the basic identity">
    Set the fields that identify the server:

    - **Name**: Use a stable name such as `survival`, `spawn`, or `build`.
    - **Type**: Choose **Server** for game servers or **Proxy** for load balancers.
    - **Server host**: Select the machine that should run this server.
    - **Activate on creation**: Enable this if the server should start immediately.
  </Step>

  <Step title="Select software">
    Choose the server software and version. For custom server jars, provide a direct download URL.

    For game servers, also choose the configurator that prepares the server files.
  </Step>

  <Step title="Set resources">
    Configure the resources assigned to this server:

    - **Memory**: Minimum and maximum memory in MB.
    - **Max players**: Player limit for this server.
  </Step>

  <Step title="Configure proxy networking">
    For proxy servers, set the **Port** for incoming player connections.
  </Step>

  <Step title="Add plugins">
    Add plugins from Modrinth, Hangar, Spigot, direct URLs, or your configured plugin sources. You can also add plugins later in server settings.
  </Step>

  <Step title="Review and create">
    Review the summary and click **Create Server**.

    <Check>
      If the server is active, SimpleCloud should start or keep one running instance for this persistent server.
    </Check>
  </Step>
</Steps>

## Understand server status

| Status | Meaning | What to check |
| ------ | ------- | ------------- |
| **Active** | The server is enabled and should run | Host availability and server logs if no instance starts |
| **Inactive** | The server is disabled | Enable it in general settings if it should run |

## Configure an existing persistent server

<AccordionGroup>
  <Accordion title="General settings">
    Enable or disable the server, adjust memory, change the player limit, and add tags for filtering.
  </Accordion>

  <Accordion title="Deployment settings">
    Persistent servers run on one assigned serverhost. Change this only when you intentionally move the server to another machine.

    <Warning>
      Moving a persistent server does not automatically move local world files. Copy required data before you start the server on a new host.
    </Warning>
  </Accordion>

  <Accordion title="Blueprint settings">
    Change the server template, including software version, configurator settings, JVM options, and runtime arguments.

    Restart the running server when it needs to pick up blueprint changes.
  </Accordion>

  <Accordion title="Properties settings">
    Add custom key-value data that your plugins and integrations can read.

    Properties are exposed to the running server as `SIMPLECLOUD_` environment variables.
  </Accordion>

  <Accordion title="Workflows settings">
    Configure automation that runs during server lifecycle events:

    - **Manual workflows**: Run on demand.
    - **On start workflows**: Run when the server starts.
    - **On stop workflows**: Run when the server stops.
  </Accordion>

  <Accordion title="Plugins settings">
    Add, inspect, or remove plugins for the server.

    Plugin changes apply the next time the server is prepared or restarted, depending on the plugin and workflow setup.
  </Accordion>

  <Accordion title="Danger zone">
    Delete the persistent server only after backing up any local data you need.

    <Warning>
      The dashboard deactivates the persistent server, waits for the running instance to stop, and then deletes the persistent server and its associated blueprint. It does not automatically back up or migrate local world files.
    </Warning>
  </Accordion>
</AccordionGroup>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Server does not start">
    **Likely cause:** The server is inactive, the assigned host is unavailable, or the host has no capacity.

    **What to check:**

    1. Confirm the server is active.
    2. Verify the assigned serverhost is online with `sc status serverhost`.
    3. Check available memory on the host.
    4. Review logs with `sc logs serverhost`.
  </Accordion>

  <Accordion title="World data is missing after moving hosts">
    **Likely cause:** The persistent server was assigned to a new host without copying local files.

    **What to check:**

    1. Stop the server.
    2. Copy the world and plugin data from the old host to the new host.
    3. Start the server again.
  </Accordion>

  <Accordion title="Plugin changes do not appear">
    **Likely cause:** The running server has not been restarted or prepared with the updated plugin set.

    Restart the server after plugin changes, then check the server logs for plugin load errors.
  </Accordion>
</AccordionGroup>
