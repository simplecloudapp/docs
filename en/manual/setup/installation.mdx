## Start in the dashboard

The dashboard is the main onboarding path. It creates or joins your network, builds the correct install command for your machine, and detects the first serverhost automatically.

<Steps>
  <Step title="Open the dashboard">
    Go to the [SimpleCloud Dashboard](https://dash.simplecloud.app) and sign in or create an account.

    You can use a magic link or one of the available SSO providers.
  </Step>

  <Step title="Create or join a network">
    Create a new network if you are starting fresh, or join an existing network with an invitation.

    After the network exists, the dashboard opens the onboarding wizard if no serverhost is connected yet.
  </Step>

  <Step title="Configure the first serverhost">
    Choose the operating system, host name, memory limit, Java runtimes, and whether SimpleCloud should start after setup.

    Linux is the recommended production target. macOS is useful for local testing. Windows setup is not available yet.
  </Step>

  <Step title="Run the generated command">
    Copy the command from the dashboard and run it on the machine that should host Minecraft servers.

    The command installs the CLI, authenticates with a generated login code, registers the machine as a serverhost, and starts it when requested.
  </Step>

  <Step title="Wait for detection">
    Keep the dashboard open while the command runs. Once the serverhost connects, the dashboard detects it and opens the main network view.
  </Step>
</Steps>

## Install the CLI later

Use this when you only need the CLI on a machine that is not going through the full onboarding flow.

<Tabs>
  <Tab title="Linux / macOS">
    ```bash
    curl -fsSL https://get.simplecloud.app | bash
    ```

    Verify the installation:

    ```bash
    simplecloud --version
    ```

    You can use `sc` anywhere the docs show `simplecloud`.
  </Tab>

  <Tab title="Windows">
    <Note>
      The CLI installer does not support Windows yet. Use Linux for production or macOS for local testing.
    </Note>
  </Tab>
</Tabs>

## Add another serverhost

After onboarding, add more machines from the dashboard instead of reusing the first setup command.

<Steps>
  <Step title="Open Server Hosts settings">
    In the dashboard, open **Settings** and go to **Server Hosts**.
  </Step>

  <Step title="Create a fresh command">
    Click **Add Host**. The dashboard creates a new login code and a command for the current network.
  </Step>

  <Step title="Run it on the new machine">
    Copy the generated command to the new machine and run it there.

    The command has this shape, but you should use the exact command from your dashboard because it includes your network, login code, and host name:

    ```bash
    curl -fsSL https://get.simplecloud.app | bash ; ~/.bun/bin/simplecloud setup \
      --yes \
      --auto-install-deps \
      --start \
      --network your-network \
      --code YOUR_LOGIN_CODE \
      --host-name host-2
    ```
  </Step>
</Steps>

## Invite team members

To add others to your network:

1. Open **Settings** in the dashboard.
2. Go to **Members**.
3. Click **Invite Member**.
4. Enter their email address and choose a role.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The dashboard cannot generate a login code">
    Close the dialog or onboarding step, open it again, and generate a fresh command.

    If the issue continues, sign out and back in so the dashboard can create a new authenticated device code.
  </Accordion>

  <Accordion title="The installer cannot download files">
    Make sure the machine can reach the internet over HTTPS.

    The installer needs outbound access to `get.simplecloud.app` and the release download hosts used by SimpleCloud.
  </Accordion>

  <Accordion title="The serverhost does not appear in the dashboard">
    1. Check whether the command finished without errors.
    2. Verify the serverhost is running with `sc status serverhost`.
    3. Review serverhost logs with `sc logs serverhost`.
    4. Generate a fresh **Add Host** command if the login code was old or copied incorrectly.
  </Accordion>

  <Accordion title="Setup fails while installing dependencies">
    Run the generated dashboard command on Linux with a user that can install required packages, or install the missing dependencies manually before retrying.

    For local testing on macOS, make sure the command runs in a normal shell with access to your user profile.
  </Accordion>
</AccordionGroup>
