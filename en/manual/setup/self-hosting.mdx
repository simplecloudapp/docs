---
title: "Self-hosting"
description: "Plan and operate a self-hosted SimpleCloud deployment with your own controller, serverhosts, and infrastructure services."
---

Self-hosting means you run the SimpleCloud control plane and infrastructure services yourself instead of relying only on the hosted dashboard defaults. Use this path when you need full control over networking, data storage, deployment location, or high-availability behavior.

<Warning>
  Self-hosting is an advanced setup. Start with the standard [installation guide](/en/manual/setup/installation) unless you already know why you need to run the controller and backing services yourself.
</Warning>

## What you run

| Component | Required | Purpose |
| --------- | -------- | ------- |
| Controller | Yes | Stores network state, reconciles desired server count, and exposes the API |
| Serverhost | Yes | Runs Minecraft server processes on each machine |
| PostgreSQL | Yes | Stores persistent controller state |
| NATS | Yes | Carries controller-to-serverhost messaging and events |
| Valkey or Redis | Optional | Caches metrics and transient data |
| ClickHouse | Optional | Stores logs and metrics when enabled |

For a deeper explanation of each component, see the [architecture overview](/en/manual/introduction/architecture/overview).

## Before you start

Make sure you have:

- At least one machine for the controller and one or more machines for serverhosts
- Reliable network connectivity between controller, NATS, PostgreSQL, and every serverhost
- A backup plan for PostgreSQL
- Monitoring for controller, NATS, PostgreSQL, disk usage, and serverhost memory
- A plan for synchronizing templates and workflows across serverhosts

<Tip>
  Keep the first self-hosted deployment small. Prove one controller, one PostgreSQL database, one NATS instance, and one serverhost before adding high availability or more hosts.
</Tip>

## Recommended rollout

<Steps>
  <Step title="Understand the architecture">
    Read the [Controller](/en/manual/introduction/architecture/controller), [Serverhost](/en/manual/introduction/architecture/serverhost), and [CLI](/en/manual/introduction/architecture/cli) pages so you know which component owns each responsibility.
  </Step>

  <Step title="Prepare infrastructure services">
    Provision PostgreSQL and NATS first. The controller depends on both before it can reconcile servers or accept API calls.

    <Check>
      You should be able to reach PostgreSQL and NATS from the controller host before starting SimpleCloud components.
    </Check>
  </Step>

  <Step title="Start the controller">
    Configure the controller to use your PostgreSQL and NATS endpoints, then start it and verify logs.

    ```bash
    sc status
    sc logs controller
    ```
  </Step>

  <Step title="Connect serverhosts">
    Install SimpleCloud on every machine that should run Minecraft servers and connect each host to your self-hosted controller.

    ```bash
    sc status serverhost
    sc logs serverhost
    ```
  </Step>

  <Step title="Synchronize shared files">
    If you run more than one serverhost, configure template, workflow, and option synchronization. See [Multi-root setup](/en/manual/setup/multi-root).
  </Step>

  <Step title="Create a test group">
    Create a small server group with `min_servers` set to `1` and confirm the controller schedules it onto a serverhost.

    <Check>
      A successful test reaches `AVAILABLE` and appears in the dashboard or `sc` output.
    </Check>
  </Step>
</Steps>

## Production checklist

<AccordionGroup>
  <Accordion title="Backups">
    Back up PostgreSQL regularly and test restore procedures. The database contains the controller's persistent state.
  </Accordion>

  <Accordion title="High availability">
    If you run multiple controller instances, only the elected leader performs reconciliation. Make sure all instances can reach the same PostgreSQL and NATS services.
  </Accordion>

  <Accordion title="Networking">
    Allow controller-to-serverhost traffic, NATS connectivity, PostgreSQL connectivity, and player-facing Minecraft/proxy ports. Keep internal services private whenever possible.
  </Accordion>

  <Accordion title="Secrets">
    Do not synchronize the `secrets/` directory between serverhosts. Each serverhost needs its own identity. See [Multi-root setup](/en/manual/setup/multi-root).
  </Accordion>

  <Accordion title="Updates">
    Update one environment first, verify server startup and shutdown, then roll changes to the rest of your hosts.
  </Accordion>
</AccordionGroup>
