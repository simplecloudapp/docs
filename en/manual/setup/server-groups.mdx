---
title: 'Server Groups'
description: 'Create scalable Minecraft server groups that share one configuration and start or stop servers based on demand.'
---

Server groups are templates for servers that should scale. Use a group when you want SimpleCloud to create multiple interchangeable servers from the same configuration, such as lobbies, minigame arenas, or proxy instances.

<Info>
  Need one long-lived server with persistent world data? Use [Persistent Servers](/en/manual/setup/persistent-servers) instead.
</Info>

## When to use a group

| Use a group when... | Use a persistent server when... |
| ------------------- | ------------------------------- |
| You need multiple servers with the same setup | You need exactly one server with long-lived data |
| Servers can be replaced without preserving local files | The server owns a world, database, or local state |
| Player demand should control server count | You want to manually choose the serverhost |
| Examples: lobbies, minigames, proxies | Examples: SMP, Citybuild, Skyblock, build servers |

## How groups work

1. You define the group configuration: software, memory, plugins, scaling, deployment, and workflows.
2. The controller compares the group's desired state with the currently running servers.
3. Serverhosts start or stop server instances to match that desired state.
4. Plugins and properties from the group are applied to every server instance.

Groups can be one of two types:

| Type | Purpose |
| ---- | ------- |
| `SERVER` | Minecraft game servers such as Paper, Purpur, Fabric, or Spigot |
| `PROXY` | Proxy servers such as Velocity or BungeeCord that route players |

## Create a group

<Steps>
  <Step title="Open the group wizard">
    In the dashboard, open **Groups** and click **New Group**.
  </Step>

  <Step title="Choose the basic identity">
    Set the fields that identify the group:

    - **Name**: Use a short, unique name such as `lobby`, `skywars`, or `proxy`.
    - **Type**: Choose **Server** for game servers or **Proxy** for load balancers.
    - **Activate on creation**: Enable this if the group should start servers immediately.
  </Step>

  <Step title="Select software">
    Choose the server software and version. For custom server jars, provide a direct download URL.

    For game servers, also choose a configurator. The configurator prepares files for the selected server software.
  </Step>

  <Step title="Set resources">
    Configure the resources each server instance receives:

    - **Memory**: Minimum and maximum memory in MB.
    - **Max players**: Player limit for each server instance.
  </Step>

  <Step title="Configure scaling">
    Choose how SimpleCloud decides when to start or stop servers.

    | Scaling mode | Use when |
    | ------------ | -------- |
    | `Slots` | You want to keep a target number of free player slots available |
    | `Servers` | You want to keep a target number of server instances available |

    Set **Min servers** to the baseline that should always run and **Max servers** to the upper limit.
  </Step>

  <Step title="Configure proxy networking">
    For proxy groups, set the **Starting port** for incoming player connections.
  </Step>

  <Step title="Add plugins">
    Add plugins from Modrinth, GitHub, direct URLs, or your configured plugin sources. You can also add plugins later in the group settings.
  </Step>

  <Step title="Review and create">
    Review the summary and click **Create Group**.

    <Check>
      After creation, an active group with `min_servers` greater than `0` should begin starting servers automatically.
    </Check>
  </Step>
</Steps>

## Understand group status

| Status | Meaning | What to check |
| ------ | ------- | ------------- |
| <Badge color="green">Healthy</Badge> | The group meets its configured server count | No action needed |
| <Badge color="blue">Scaling</Badge> | SimpleCloud is starting or stopping servers | Wait for the next reconciliation cycle |
| <Badge color="red">Down</Badge> | No servers are running | Activation, minimum servers, deployment hosts, and host resources |
| <Badge color="orange">Inactive</Badge> | The group is disabled | Enable the group in general settings |
| <Badge color="gray">Disabled</Badge> | Minimum servers is `0` | Increase minimum servers if the group should run |

## Configure an existing group

Most changes happen in the group's settings page. Open only the section you need.

<AccordionGroup>
  <Accordion title="General settings">
    Use this section to enable or disable scaling, adjust memory, change player limits, and add tags for filtering.

    <Tip>
      Tags are useful for dashboards, automation, and API queries. Use stable labels such as `region:eu`, `mode:lobby`, or `environment:prod`.
    </Tip>
  </Accordion>

  <Accordion title="Scaling settings">
    Fine-tune how many servers SimpleCloud keeps online.

    | Setting | Purpose |
    | ------- | ------- |
    | **Scaling mode** | Choose whether scaling is based on free slots or server count |
    | **Start policy** | Decide whether servers start immediately or only replace deleted servers |
    | **Min servers** | Keep this many servers running whenever the group is active |
    | **Max servers** | Prevent the group from scaling beyond this count |
    | **Player threshold** | Start more servers when usage crosses this percentage |
    | **Available slots** | Keep this many player slots free across the group |
    | **Idle time** | Stop idle servers after this duration |
  </Accordion>

  <Accordion title="Deployment settings">
    Choose which serverhosts may run the group.

    - Enable hosts that are allowed to run servers for this group.
    - Disable hosts that should not receive deployments.
    - Reorder hosts when you need a preferred host order.

    <Tip>
      If every host is enabled, SimpleCloud distributes servers automatically. Disable hosts only when you need placement control.
    </Tip>
  </Accordion>

  <Accordion title="Blueprint settings">
    Change the server template behind the group, including software version, configurator settings, JVM options, and runtime arguments.

    Changes affect new server instances. Running servers may need a restart before they pick up template changes.
  </Accordion>

  <Accordion title="Properties settings">
    Add custom key-value data that your plugins and integrations can read.

    Properties are available through the [Cloud API](/en/developer/api/groups) and as `SIMPLECLOUD_` environment variables on running servers.
  </Accordion>

  <Accordion title="Workflows settings">
    Configure automation that runs during server lifecycle events:

    - **Manual workflows**: Run on demand.
    - **On start workflows**: Run when a server starts.
    - **On stop workflows**: Run when a server stops.
  </Accordion>

  <Accordion title="Plugins settings">
    Add, inspect, or remove plugins installed for every server in the group.

    Plugin changes apply to newly prepared servers. Restart or recreate running servers if they need the updated plugin set.
  </Accordion>

  <Accordion title="Danger zone">
    Delete the group only after you understand the impact.

    <Warning>
      Deleting a group removes its configuration. It does not delete already running server processes. Stop servers first if you want a clean shutdown.
    </Warning>
  </Accordion>
</AccordionGroup>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Servers stay in QUEUED">
    **Likely cause:** No serverhost is available or the allowed hosts have no capacity.

    **What to check:**

    1. Run `sc status serverhost`.
    2. Verify deployment settings allow at least one host.
    3. Check available memory on the host.
    4. Review controller logs with `sc logs controller`.
  </Accordion>

  <Accordion title="Group shows Down">
    **Likely cause:** The group is not configured to keep any servers online.

    **What to check:**

    1. Enable the group.
    2. Set **Min servers** to at least `1`.
    3. Enable at least one serverhost in deployment settings.
    4. Verify the selected host has enough free memory.
  </Accordion>

  <Accordion title="Servers do not scale up">
    **Likely cause:** The scaling threshold has not been reached or the group is already at its maximum server count.

    **What to check:**

    1. Confirm the scaling mode matches your goal.
    2. Lower the player threshold if scaling starts too late.
    3. Increase **Max servers** if the group is capped.
    4. Verify servers report player counts.
  </Accordion>

  <Accordion title="Servers scale down too quickly">
    **Likely cause:** Idle time is too short or the scaling target is too aggressive.

    **What to check:**

    1. Increase idle time, for example from `1m` to `5m`.
    2. Raise the player threshold.
    3. Increase **Min servers** if you always need a baseline online.
  </Accordion>

  <Accordion title="Servers stay in PREPARING">
    **Likely cause:** A workflow, blueprint, plugin download, or filesystem operation fails during preparation.

    **What to check:**

    1. Review serverhost logs with `sc logs serverhost`.
    2. Check disk space.
    3. Verify plugin download URLs.
    4. Confirm template and workflow paths exist.
  </Accordion>

  <Accordion title="Orphaned server records remain">
    **Likely cause:** A server process stopped without the controller recording the lifecycle event, for example after a host crash.

    Use the `DELETE /v0/servers/database` REST API endpoint to remove the stale record. See [Delete server record](/en/developer/api/servers#delete-server-record).

    <Warning>
      This only removes the database row. It does not stop a running process or trigger cleanup workflows.
    </Warning>
  </Accordion>
</AccordionGroup>
