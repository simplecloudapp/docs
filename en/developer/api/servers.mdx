---
title: 'Servers API'
description: 'Query and manage running server instances'
---

The Servers API manages running server instances. Use it to query, stop, and update servers via `api.server()`.

<Info>
  Starting a new group server is handled by the Groups API with `api.group().requestServerStart(...)`. The Servers API only works with server instances that already exist.
</Info>

## Get Servers

```java
// Get all servers
api.server().getAllServers()
    .thenAccept(servers -> System.out.println("Total: " + servers.size()));

// Get servers with query filters
ServerQuery query = ServerQuery.create()
    .filterByServerGroupName("lobby")
    .filterByState(ServerState.AVAILABLE, ServerState.INGAME)
    .sortBy("numerical_id")
    .sortOrder("asc");

api.server().getAllServers(query)
    .thenAccept(servers -> servers.forEach(server ->
        System.out.println(server.getServerId() + ": " + server.getState())));

// Get server by ID
api.server().getServerById("server-uuid")
    .thenAccept(server -> System.out.println(server.getState()));

// Get servers in a group
api.server().getServersByGroup("lobby")
    .thenAccept(servers -> servers.forEach(server ->
        System.out.println(server.getServerId() + ": " + server.getState())));

// Get server by group and numerical ID, for example Lobby-1
api.server().getServerByNumericalId("lobby", 1)
    .thenAccept(server -> System.out.println(server.getServerId()));

// Get current server from inside a running server
api.server().getCurrentServer()
    .thenAccept(server -> System.out.println("Running on: " + server.getServerId()));
```

## Request a Group Server

Queue one new server start for a group with `api.group()`. The reconciler processes the request on its next tick and creates the server when group limits allow it.

```java
api.group().getGroupByName("lobby")
    .thenCompose(group -> {
        if (group == null) {
            return CompletableFuture.failedFuture(
                new IllegalArgumentException("Group not found: lobby"));
        }
        return api.group().requestServerStart(group);
    })
    .thenRun(() -> System.out.println("Start request accepted for lobby"));
```

<Note>
  `requestServerStart` completes when the request is accepted, not when the server is ready. Subscribe to `api.event().server().onStateChanged(...)` or query the group to find the new server once it reaches `AVAILABLE`.
</Note>

## Stop Server

```java
api.server().stopServer("server-uuid")
    .thenRun(() -> System.out.println("Stop requested"));
```

### Stop Server (REST)

Use `DELETE /v0/servers` when you want the controller to stop the server normally and run the server lifecycle.

<RequestExample>
  ```bash cURL
  curl -X DELETE "https://your-controller/v0/servers?server_id=123e4567-e89b-12d3-a456-426614174000" \
    -H "X-Network-ID: your-network-id" \
    -H "X-Network-Secret: your-network-secret"
  ```
</RequestExample>

<ResponseExample>
  ```json 200 OK
  {
    "message": "Server stop request sent successfully",
    "server_id": "123e4567-e89b-12d3-a456-426614174000",
    "state": "STOPPING"
  }
  ```
</ResponseExample>

<ParamField query="server_id" type="string" required>
  ID of the server instance to stop.
</ParamField>

## Update Server

```java
UpdateServerRequest update = UpdateServerRequest.builder()
    .maxPlayers(64)
    .build();

api.server().updateServer("server-uuid", update)
    .thenAccept(server -> System.out.println("Updated: " + server.getMaxPlayers()));
```

## Server Properties

Servers inherit properties from their group or persistent server, but you can override them per instance:

```java
// Add or update properties (merges with existing)
Map<String, Object> props = Map.of("map", "castle", "mode", "competitive");
api.server().updateServerProperties("server-uuid", props)
    .thenAccept(updated -> System.out.println("Properties: " + updated));

// Remove specific properties
api.server().deleteServerProperties("server-uuid", List.of("mode"));
```

## List Servers (REST)

To list servers in a network with optional filters, use the REST API endpoint `GET /v0/servers`. The response includes server details, group or persistent server metadata, blueprint information, and workflow configurations.

<RequestExample>
  ```bash cURL
  curl "https://your-controller/v0/servers?state=AVAILABLE&type=lobby" \
    -H "X-Network-ID: your-network-id" \
    -H "X-Network-Secret: your-network-secret"
  ```
</RequestExample>

<ResponseExample>
  ```json 200 OK
  {
    "count": 1,
    "servers": [
      {
        "server_id": "123e4567-e89b-12d3-a456-426614174000",
        "network_id": "production",
        "server_group_id": "lobby",
        "persistent_server_id": null,
        "serverhost_id": "host-eu-1",
        "numerical_id": 1,
        "ip": "127.0.0.1",
        "port": 25565,
        "state": "AVAILABLE",
        "player_count": 12,
        "max_players": 100,
        "min_memory": 512,
        "max_memory": 1024,
        "properties": {
          "map": "castle"
        }
      }
    ]
  }
  ```
</ResponseExample>

<ParamField header="X-Network-ID" type="string" required>
  Your network identifier.
</ParamField>

<ParamField header="X-Network-Secret" type="string" required>
  Your network secret.
</ParamField>

<ParamField header="X-SC-Component" type="string">
  Optional caller component name attached to the controller request event.
</ParamField>

<ParamField query="server_group_id" type="string">
  Filter by one or more server group IDs. Use commas to pass multiple IDs.
</ParamField>

<ParamField query="state" type="string">
  Filter by one or more server states, for example `AVAILABLE,STARTING`.
</ParamField>

<ParamField query="serverhost_id" type="string">
  Filter by serverhost ID.
</ParamField>

<ParamField query="persistent_server_id" type="string">
  Filter by persistent server ID.
</ParamField>

<ParamField query="type" type="string">
  Filter by server group or persistent server type.
</ParamField>

<ParamField query="name" type="string">
  Filter by server group or persistent server name.
</ParamField>

<ParamField query="tags" type="string">
  Filter by group or persistent server tags.
</ParamField>

<ParamField query="numerical_id" type="string">
  Filter by one or more numerical IDs. Use commas to pass multiple IDs.
</ParamField>

<ParamField query="sort_by" type="string">
  Sort field. Supported values are `created_at`, `updated_at`, `numerical_id`, and `state`.
</ParamField>

<ParamField query="sort_order" type="string">
  Sort order. Use `asc` or `desc`.
</ParamField>

### Response Cache

The controller can cache database rows for `GET /v0/servers` for 2 seconds to reduce load from dashboards and polling clients. When active, responses include `X-DB-Cache: HIT` or `X-DB-Cache: MISS`. Permission-filtered requests always bypass this cache.

## Delete Server Record

To remove a stale server record directly from the database without stopping a process or publishing lifecycle events, use `DELETE /v0/servers/database`.

<Warning>
  This operation only removes the database row. It does not stop the server process, trigger cleanup workflows, or emit lifecycle events. Use `stopServer` for normal shutdown.
</Warning>

<RequestExample>
  ```bash cURL
  curl -X DELETE "https://your-controller/v0/servers/database?server_id=123e4567-e89b-12d3-a456-426614174000" \
    -H "X-Network-ID: your-network-id" \
    -H "X-Network-Secret: your-network-secret"
  ```
</RequestExample>

<ResponseExample>
  ```json 200 OK
  {
    "message": "Server row deleted successfully",
    "server_id": "123e4567-e89b-12d3-a456-426614174000"
  }
  ```
</ResponseExample>

<ParamField query="server_id" type="string" required>
  ID of the server row to remove from the database.
</ParamField>

## ServerState

| State | Description |
|-------|-------------|
| `UNKNOWN_STATE` | Unknown or unspecified state |
| `PREPARING` | Preparing files and runtime data |
| `STARTING` | Server process is starting |
| `AVAILABLE` | Ready for players |
| `INGAME` | In game with active players |
| `STOPPING` | Shutdown is in progress |
| `CLEANUP` | Server stopped and cleanup is running |

## Environment Variables

Inside a running server, access server info without the API:

```java
String group = System.getenv("SIMPLECLOUD_GROUP");
String uniqueId = System.getenv("SIMPLECLOUD_UNIQUE_ID");
String numericalId = System.getenv("SIMPLECLOUD_NUMERICAL_ID");
String host = System.getenv("SIMPLECLOUD_HOST");
String ip = System.getenv("SIMPLECLOUD_IP");
String port = System.getenv("SIMPLECLOUD_PORT");
String maxPlayers = System.getenv("SIMPLECLOUD_MAX_PLAYERS");
String maxMemory = System.getenv("SIMPLECLOUD_MAX_MEMORY");
```

Custom group properties are also available with the `SIMPLECLOUD_` prefix. Property names are uppercased and dashes become underscores.
