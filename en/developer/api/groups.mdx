title: 'Groups API'

The Groups API lets you create, query, update, and delete server groups. Access it via `api.group()`.

## Get Groups

```java
// Get all groups
api.group().getAllGroups()
    .thenAccept(groups -> groups.forEach(g -> System.out.println(g.getName())));

// Get all groups with query filters
GroupQuery query = GroupQuery.create()
    .filterByName("lobby")
    .filterByType(GroupServerType.SERVER);

api.group().getAllGroups(query)
    .thenAccept(groups -> groups.forEach(group ->
        System.out.println(group.getServerGroupId())));

// Get group by name
api.group().getGroupByName("lobby")
    .thenAccept(group -> System.out.println(group.getServerGroupId()));

// Get group by ID
api.group().getGroupById("group-uuid")
    .thenAccept(group -> System.out.println(group.getName()));
```

## Create Group

```java
CreateGroupRequest request = CreateGroupRequest.builder()
    .name("bedwars")
    .type(GroupServerType.SERVER)
    .minMemory(512)
    .maxMemory(1024)
    .maxPlayers(16)
    .minOnlineCount(1)
    .maxOnlineCount(10)
    .build();

api.group().createGroup(request)
    .thenAccept(group -> System.out.println("Created: " + group.getServerGroupId()));
```

## Update Group

```java
UpdateGroupRequest update = UpdateGroupRequest.builder()
    .maxPlayers(32)
    .maxOnlineCount(20)
    .build();

api.group().updateGroup("group-uuid", update)
    .thenAccept(group -> System.out.println("Updated: " + group.getName()));
```

## Delete Group

```java
api.group().deleteGroup("group-uuid")
    .thenRun(() -> System.out.println("Deleted group-uuid"));
```

<Warning>
  Deleting a group doesn't stop running servers. Stop servers first if needed.
</Warning>

## Group Properties

Groups support custom key-value properties for metadata:

```java
// Add or update properties (merges with existing)
Map<String, Object> props = Map.of(
    "gameMode", "ADVENTURE",
    "region", "eu-west"
);
api.group().updateGroupProperties("group-uuid", props);

// Remove specific properties
api.group().deleteGroupProperties("group-uuid", List.of("region"));
```

Properties are available in servers as environment variables prefixed with `SIMPLECLOUD_`.

## ScalingConfig

<ResponseField name="min_servers" type="integer" required>
  Minimum number of servers to keep running.
</ResponseField>

<ResponseField name="max_servers" type="integer" required>
  Maximum number of servers allowed.
</ResponseField>

<ResponseField name="scaling_mode" type="ScalingMode" required>
  Scaling strategy. Use `SLOTS` to maintain free player slots or `SERVERS` to scale by server count.
</ResponseField>

<ResponseField name="available_slots" type="integer">
  Open slots to maintain when `scaling_mode` is `SLOTS`.
</ResponseField>

<ResponseField name="player_threshold" type="number">
  Scale-up threshold between `0` and `1`.
</ResponseField>

<ResponseField name="scale_down" type="ScaleDownConfig" required>
  Scale-down behavior settings.
</ResponseField>

## Server start queue

Groups using the `SERVERS` scaling mode support a manual start queue. Instead of starting a server immediately, you can request a queued start that the reconciler processes on its next tick. This is useful when you want to control exactly when new servers are created while still respecting the group's `max_servers` limit.

<Info>
  The start queue is only available for groups using the `SERVERS` scaling mode. Groups using `SLOTS` mode do not support queued starts.
</Info>

### Queue a server start

You can request a start by passing the server group ID directly or by resolving a `Group` first:

```java
// Request a start by server group ID
api.group().requestServerStart("group-uuid")
    .thenRun(() -> System.out.println("Start request accepted"));

// Request a start using the Group overload
api.group().getGroupByName("lobby")
    .thenCompose(group -> {
        if (group == null) {
            return CompletableFuture.failedFuture(
                new IllegalArgumentException("Group not found: lobby"));
        }
        return api.group().requestServerStart(group);
    })
    .thenRun(() -> System.out.println("Start request accepted for lobby"));
```

The reconciler picks up queued starts on the next reconciliation tick and attempts to allocate a server. If the group is at its `max_servers` limit, the queued start is marked as `FAILED` with a reason.

### List queued starts

```java
api.group().getServerStartQueue()
    .thenAccept(queue -> {
        System.out.println("Groups with queue data: " + queue.getCount());
        System.out.println("Queued starts: " + queue.getQueuedStarts());
        System.out.println("Failed starts: " + queue.getFailedStarts());

        GroupStartQueueEntry lobby = queue.findByServerGroupName("lobby");
        if (lobby != null) {
            System.out.println("Lobby starts: " + lobby.getTotalStarts());
        }
    });
```

### Clear queued starts

Remove all pending and failed starts for a specific group:

```java
api.group().clearServerStartQueue("group-uuid")
    .thenRun(() -> System.out.println("Cleared queue for group-uuid"));
```

### Queue overview model

`getServerStartQueue()` returns a `GroupStartQueue`.

<ResponseField name="count" type="integer" required>
  Number of groups with queue data.
</ResponseField>

<ResponseField name="queuedStarts" type="integer" required>
  Number of queued starts across all groups.
</ResponseField>

<ResponseField name="failedStarts" type="integer" required>
  Number of failed starts across all groups.
</ResponseField>

<ResponseField name="totalStarts" type="integer" required>
  Total number of queue items across all groups.
</ResponseField>

<ResponseField name="items" type="List<GroupStartQueueEntry>" required>
  Queue data grouped by server group.
</ResponseField>

### Queue entry model

Each `GroupStartQueueEntry` describes the queue state for one server group.

<ResponseField name="serverGroupId" type="string | null">
  Server group ID.
</ResponseField>

<ResponseField name="serverGroupName" type="string | null">
  Server group name.
</ResponseField>

<ResponseField name="queuedStarts" type="integer" required>
  Number of pending starts for the group.
</ResponseField>

<ResponseField name="failedStarts" type="integer" required>
  Number of failed starts for the group.
</ResponseField>

<ResponseField name="totalStarts" type="integer" required>
  Total number of queue items for the group.
</ResponseField>

<ResponseField name="starts" type="List<GroupStartQueueItem>" required>
  Persisted queue items for the group.
</ResponseField>

### Queue item model

Each `GroupStartQueueItem` represents one persisted start request.

<ResponseField name="id" type="string" required>
  Unique identifier for the queued start.
</ResponseField>

<ResponseField name="createdAt" type="string | null">
  Timestamp when the start was queued, in ISO 8601 format.
</ResponseField>

<ResponseField name="status" type="GroupStartQueueItemStatus" required>
  Queue item status. Possible values are `PENDING`, `FAILED`, and `UNKNOWN`.
</ResponseField>

<ResponseField name="failureReason" type="string | null">
  Reason for failure, if applicable.
</ResponseField>

<Warning>
  Failed starts are automatically cleaned up after 1 hour. Use the list endpoint to check for failures and requeue if needed.
</Warning>

## GroupServerType

| Value | Description |
|-------|-------------|
| `SERVER` | Game server (Paper, Spigot, etc.) |
| `PROXY` | Proxy server (Velocity, BungeeCord) |
