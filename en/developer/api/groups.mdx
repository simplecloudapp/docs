---
title: 'Groups API'
description: 'Manage server groups programmatically'
---

The Groups API lets you create, query, update, and delete server groups. Access it via `api.group()`.

## Get Groups

<CodeGroup>
```java Java
// Get all groups
api.group().getAllGroups()
    .thenAccept(groups -> groups.forEach(g -> System.out.println(g.getName())));

// Get all groups with query filters
GroupQuery query = GroupQuery.create()
    .filterByType(GroupServerType.SERVER)
    .filterByTag("minigame")
    .sortBy("name")
    .sortOrder("asc")
    .limit(10);
api.group().getAllGroups(query)
    .thenAccept(groups -> groups.forEach(g -> System.out.println(g.getName())));

// Get group by name
api.group().getGroupByName("lobby")
    .thenAccept(group -> System.out.println(group.getServerGroupId()));

// Get group by ID
api.group().getGroupById("group-uuid")
    .thenAccept(group -> System.out.println(group.getName()));
```

```kotlin Kotlin
// in a coroutine scope (e.g. plugin lifecycle or launch { })

// Get all groups
val groups = api.group().getAllGroups().await()
groups.forEach { g -> println(g.name) }

// Get all groups with query filters
val query = GroupQuery.create()
    .filterByType(GroupServerType.SERVER)
    .filterByTag("minigame")
    .sortBy("name")
    .sortOrder("asc")
    .limit(10)
val filteredGroups = api.group().getAllGroups(query).await()
filteredGroups.forEach { g -> println(g.name) }

// Get group by name
val group = api.group().getGroupByName("lobby").await()
println(group.serverGroupId)

// Get group by ID
val groupById = api.group().getGroupById("group-uuid").await()
println(groupById.name)
```
</CodeGroup>

## GroupQuery

Use `GroupQuery.create()` to build filtered queries:

| Method | Description |
|--------|-------------|
| `filterByType(GroupServerType)` | Filter by server type (`SERVER`, `PROXY`, `UNKNOWN_SERVER`) |
| `filterByTag(String)` | Filter by a single tag |
| `sortBy(String)` | Sort field: `"name"` or other group fields |
| `sortOrder(String)` | `"asc"` or `"desc"` |
| `limit(Integer)` | Maximum number of results to return |

## Create Group

`CreateGroupRequest` uses a constructor + setter chaining pattern:

<CodeGroup>
```java Java
ScalingConfig scaling = new ScalingConfig();
scaling.setMinServers(1);
scaling.setMaxServers(10);
scaling.setScalingMode(ScalingMode.SLOTS);
scaling.setAvailableSlots(4);

SourceConfig source = new SourceConfig();
source.setType(SourceType.BLUEPRINT);
source.setBlueprint("paper-1.21");

CreateGroupRequest request = new CreateGroupRequest("bedwars")
    .setType(GroupServerType.SERVER)
    .setMinMemory(512)
    .setMaxMemory(1024)
    .setMaxPlayers(16)
    .setActive(true)
    .setScaling(scaling)
    .setSource(source);

api.group().createGroup(request)
    .thenAccept(group -> System.out.println("Created: " + group.getServerGroupId()));
```

```kotlin Kotlin
val scaling = ScalingConfig().apply {
    minServers = 1
    maxServers = 10
    scalingMode = ScalingMode.SLOTS
    availableSlots = 4
}

val source = SourceConfig().apply {
    type = SourceType.BLUEPRINT
    blueprint = "paper-1.21"
}

val request = CreateGroupRequest("bedwars")
    .setType(GroupServerType.SERVER)
    .setMinMemory(512)
    .setMaxMemory(1024)
    .setMaxPlayers(16)
    .setActive(true)
    .setScaling(scaling)
    .setSource(source)

val createdGroup = api.group().createGroup(request).await()
println("Created: ${createdGroup.serverGroupId}")
```
</CodeGroup>

## Update Group

`UpdateGroupRequest` follows the same constructor + setter pattern. Only fields you set are changed:

<CodeGroup>
```java Java
UpdateGroupRequest update = new UpdateGroupRequest()
    .setMaxPlayers(32)
    .setActive(true);

api.group().updateGroup("group-uuid", update)
    .thenAccept(group -> System.out.println("Updated: " + group.getName()));
```

```kotlin Kotlin
val update = UpdateGroupRequest()
    .setMaxPlayers(32)
    .setActive(true)

val updatedGroup = api.group().updateGroup("group-uuid", update).await()
println("Updated: ${updatedGroup.name}")
```
</CodeGroup>

## Delete Group

<CodeGroup>
```java Java
api.group().deleteGroup("group-uuid")
    .thenRun(() -> System.out.println("Deleted"));
```

```kotlin Kotlin
api.group().deleteGroup("group-uuid").await()
println("Deleted")
```
</CodeGroup>

<Warning>
  Deleting a group does not stop running servers. It prevents new servers from being created for that group.
</Warning>

## Group Properties

Groups support custom properties for metadata. Values can be any JSON-compatible type:

<CodeGroup>
```java Java
// Add or update properties (deep merge with existing)
api.group().updateGroupProperties("group-uuid", Map.of(
    "gameMode", "ADVENTURE",
    "region", "eu-west"
)).thenAccept(props -> System.out.println("Updated properties: " + props));

// Update a single property
api.group().updateGroupProperty("group-uuid", "region", "us-east")
    .thenAccept(props -> System.out.println("Updated: " + props));

// Remove specific properties
api.group().deleteGroupProperties("group-uuid", List.of("region"))
    .thenAccept(remaining -> System.out.println("Remaining: " + remaining));

// Remove a single property
api.group().deleteGroupProperty("group-uuid", "region")
    .thenAccept(remaining -> System.out.println("Remaining: " + remaining));
```

```kotlin Kotlin
// Add or update properties (deep merge with existing)
val props = api.group().updateGroupProperties("group-uuid", mapOf(
    "gameMode" to "ADVENTURE",
    "region" to "eu-west"
)).await()
println("Updated properties: $props")

// Update a single property
val updatedProps = api.group().updateGroupProperty("group-uuid", "region", "us-east").await()
println("Updated: $updatedProps")

// Remove specific properties
val remaining = api.group().deleteGroupProperties("group-uuid", listOf("region")).await()
println("Remaining: $remaining")

// Remove a single property
val remainingAfter = api.group().deleteGroupProperty("group-uuid", "region").await()
println("Remaining: $remainingAfter")
```
</CodeGroup>

## Group Model

<ResponseField name="serverGroupId" type="String">
  Unique identifier for the group.
</ResponseField>

<ResponseField name="name" type="String">
  Human-readable group name.
</ResponseField>

<ResponseField name="type" type="GroupServerType">
  Server type: `SERVER`, `PROXY`, or `UNKNOWN_SERVER`.
</ResponseField>

<ResponseField name="minMemory" type="Integer">
  Minimum memory allocation in MB.
</ResponseField>

<ResponseField name="maxMemory" type="Integer">
  Maximum memory allocation in MB.
</ResponseField>

<ResponseField name="maxPlayers" type="Integer">
  Maximum players per server instance.
</ResponseField>

<ResponseField name="active" type="Boolean">
  Whether the group is active. Inactive groups do not spawn new servers.
</ResponseField>

<ResponseField name="priority" type="Integer">
  Group priority (lower number = higher priority).
</ResponseField>

<ResponseField name="scaling" type="ScalingConfig">
  Auto-scaling configuration.
</ResponseField>

<ResponseField name="deployment" type="DeploymentConfig">
  Deployment host and strategy configuration.
</ResponseField>

<ResponseField name="source" type="SourceConfig">
  Source configuration (blueprint or container image).
</ResponseField>

<ResponseField name="workflows" type="WorkflowsConfig">
  Workflow triggers for server lifecycle events.
</ResponseField>

<ResponseField name="properties" type="Map<String, Object>">
  Custom metadata as a key-value map.
</ResponseField>

<ResponseField name="tags" type="List<String>">
  Tags for organization and filtering.
</ResponseField>

<ResponseField name="createdAt" type="String">
  ISO 8601 creation timestamp.
</ResponseField>

<ResponseField name="updatedAt" type="String">
  ISO 8601 last-updated timestamp.
</ResponseField>

## GroupServerType

| Value | Description |
|-------|-------------|
| `SERVER` | Game server (Paper, Spigot, etc.) |
| `PROXY` | Proxy server (Velocity, BungeeCord) |
| `UNKNOWN_SERVER` | Unknown or unspecified type |

## ScalingConfig

Controls how many servers run and when to scale:

| Property | Type | Description |
|----------|------|-------------|
| `minServers` | `int` | Minimum servers to keep running |
| `maxServers` | `int` | Maximum servers allowed |
| `scalingMode` | `ScalingMode` | `SLOTS`, `PLAYERS`, or `MANUAL` |
| `availableSlots` | `int` | Free slots to maintain across the group (SLOTS mode) |
| `playerThreshold` | `double` | Scale-up threshold between 0.0 and 1.0 (PLAYERS mode) |
| `scaleDown` | `ScaleDownConfig` | Scale-down behavior |

### ScalingMode

| Value | Description |
|-------|-------------|
| `SLOTS` | Scale based on available player slots across the group |
| `PLAYERS` | Scale based on player count relative to `playerThreshold` |
| `MANUAL` | No automatic scaling; only manual starts |

### ScaleDownConfig

| Property | Type | Description |
|----------|------|-------------|
| `idleTime` | `String` | Duration a server must be idle before scale-down (e.g. `"5m"`) |
| `ignorePlayers` | `boolean` | Scale down even if players are present |

## DeploymentConfig

Controls which hosts run servers and how they are distributed:

| Property | Type | Description |
|----------|------|-------------|
| `hosts` | `DeploymentHost[]` | List of eligible hosts |
| `strategy` | `DeploymentStrategy` | `RANDOM`, `PRIORITY`, or `ROUND_ROBIN` |

### DeploymentHost

| Property | Type | Description |
|----------|------|-------------|
| `name` | `String` | Host name or identifier |
| `priority` | `int` | Priority for `PRIORITY` strategy (lower = preferred) |

### DeploymentStrategy

| Value | Description |
|-------|-------------|
| `RANDOM` | Randomly select a host |
| `PRIORITY` | Prefer hosts with lower priority numbers |
| `ROUND_ROBIN` | Distribute servers evenly across hosts |

## SourceConfig

Defines where server software comes from:

| Property | Type | Description |
|----------|------|-------------|
| `type` | `SourceType` | `BLUEPRINT` or `IMAGE` |
| `blueprint` | `String` | Blueprint name (when type is `BLUEPRINT`) |
| `image` | `String` | Container image reference (when type is `IMAGE`) |

## WorkflowsConfig

Defines automated workflows triggered by server lifecycle events:

| Property | Type | Description |
|----------|------|-------------|
| `manual` | `List<String>` | Workflow IDs available for manual execution |
| `when` | `WorkflowWhen` | Automatic trigger configuration |

### WorkflowWhen

| Property | Type | Description |
|----------|------|-------------|
| `start` | `List<String>` | Workflow IDs to run when a server starts |
| `stop` | `List<String>` | Workflow IDs to run when a server stops |

## Server Start Queue

The start queue lets you request server starts that the reconciler processes on its next tick. This is useful when you want to control new server creation while still respecting the group's `maxServers` limit.

### Queue a server start

<CodeGroup>
```java Java
// Request a start by server group ID
api.group().requestServerStart("group-uuid")
    .thenRun(() -> System.out.println("Start request accepted"));

// Request a start using a Group object
api.group().getGroupByName("lobby")
    .thenCompose(group -> api.group().requestServerStart(group))
    .thenRun(() -> System.out.println("Start request accepted for lobby"));
```

```kotlin Kotlin
// Request a start by server group ID
api.group().requestServerStart("group-uuid").await()
println("Start request accepted")

// Request a start using a Group object
val lobbyGroup = api.group().getGroupByName("lobby").await()
api.group().requestServerStart(lobbyGroup).await()
println("Start request accepted for lobby")
```
</CodeGroup>

### Inspect the queue

<CodeGroup>
```java Java
api.group().getServerStartQueue()
    .thenAccept(queue -> {
        System.out.println("Groups with queue data: " + queue.getCount());
        System.out.println("Total queued starts: " + queue.getQueuedStarts());
        System.out.println("Total failed starts: " + queue.getFailedStarts());

        // Look up a specific group
        GroupStartQueueEntry lobby = queue.findByServerGroupName("lobby");
        if (lobby != null) {
            System.out.println("Lobby starts: " + lobby.getTotalStarts());
            for (GroupStartQueueItem item : lobby.getStarts()) {
                System.out.println("  " + item.getId() + ": " + item.getStatus());
                if (item.getFailureReason() != null) {
                    System.out.println("  Reason: " + item.getFailureReason());
                }
            }
        }
    });
```

```kotlin Kotlin
val queue = api.group().getServerStartQueue().await()
println("Groups with queue data: ${queue.count}")
println("Total queued starts: ${queue.queuedStarts}")
println("Total failed starts: ${queue.failedStarts}")

// Look up a specific group
val lobby = queue.findByServerGroupName("lobby")
if (lobby != null) {
    println("Lobby starts: ${lobby.totalStarts}")
    for (item in lobby.starts) {
        println("  ${item.id}: ${item.status}")
        if (item.failureReason != null) {
            println("  Reason: ${item.failureReason}")
        }
    }
}
```
</CodeGroup>

### Clear the queue

<CodeGroup>
```java Java
// Clear all queued starts for a group by ID
api.group().clearServerStartQueue("group-uuid")
    .thenRun(() -> System.out.println("Queue cleared"));

// Clear using a Group object
api.group().getGroupByName("lobby")
    .thenCompose(group -> api.group().clearServerStartQueue(group))
    .thenRun(() -> System.out.println("Queue cleared for lobby"));
```

```kotlin Kotlin
// Clear all queued starts for a group by ID
api.group().clearServerStartQueue("group-uuid").await()
println("Queue cleared")

// Clear using a Group object
val lobbyGroup = api.group().getGroupByName("lobby").await()
api.group().clearServerStartQueue(lobbyGroup).await()
println("Queue cleared for lobby")
```
</CodeGroup>

### GroupStartQueue model

| Property | Type | Description |
|----------|------|-------------|
| `count` | `int` | Number of groups with queue data |
| `queuedStarts` | `int` | Pending starts across all groups |
| `failedStarts` | `int` | Failed starts across all groups |
| `totalStarts` | `int` | Total queue items across all groups |
| `items` | `List<GroupStartQueueEntry>` | Queue data per group |

### GroupStartQueueEntry model

| Property | Type | Description |
|----------|------|-------------|
| `serverGroupId` | `String?` | Server group ID |
| `serverGroupName` | `String?` | Server group name |
| `queuedStarts` | `int` | Pending starts for this group |
| `failedStarts` | `int` | Failed starts for this group |
| `totalStarts` | `int` | Total queue items for this group |
| `starts` | `List<GroupStartQueueItem>` | Individual queue items |

### GroupStartQueueItem model

| Property | Type | Description |
|----------|------|-------------|
| `id` | `String?` | Unique identifier for this queue item |
| `createdAt` | `String?` | ISO 8601 timestamp when the start was queued |
| `status` | `GroupStartQueueItemStatus` | `PENDING`, `FAILED`, or `UNKNOWN` |
| `failureReason` | `String?` | Reason for failure, if applicable |

<Warning>
  If the group is at its `maxServers` limit, the queued start is marked `FAILED`. Failed starts are automatically cleaned up after one hour.
</Warning>
