Ein Server ist eine einzelne laufende Instanz, die aus einer Gruppe oder einem persistenten Server erstellt wurde. Mit `api.server()` kannst du diese Instanz untersuchen und verwalten. Um zu ändern, wie Server erstellt werden, aktualisiere stattdessen die zugehörige [Gruppe](/de/developer/api/groups) oder den zugehörigen [persistenten Server](/de/developer/api/persistent-servers).

<Note>
  Die Ausschnitte auf dieser Referenzseite zeigen einzelne API-Aufrufe. Sie verwenden `api` für den unter [Installation](/de/developer/installation) erzeugten gemeinsamen `CloudApi`-Client und gehören in die Methoden deines Plugins.
</Note>

## Verfügbare Kapazität finden

Mit `ServerQuery` kannst du Instanzen nach Quelle, Zustand, Host oder numerischer ID suchen. Dieses Beispiel berechnet die gemeldeten freien Plätze aller spielbereiten Lobby-Server:

```java
ServerQuery query = ServerQuery.create()
    .filterByServerGroupName("lobby")
    .filterByState(ServerState.AVAILABLE, ServerState.INGAME);

api.server().getAllServers(query)
    .thenApply(servers -> servers.stream()
        .filter(server -> server.getPlayerCount() != null)
        .mapToInt(server -> Math.max(
            0,
            server.getMaxPlayers() - server.getPlayerCount()
        ))
        .sum())
    .thenAccept(capacity ->
        System.out.println("Lobby-Kapazität: " + capacity));
```

Das Ergebnis ist eine Momentaufnahme und keine Reservierung. Wenn du damit auswählst, mit welchem Server ein Spieler verbunden werden soll, behalte die Routing-Regeln in deiner Anwendung und verarbeite das Verbindungsergebnis. Unter [Spieler mit Autoscaling weiterleiten](/de/developer/guides/server-management) findest du einen vollständigen Routing-Ablauf.

Rufe `getAllServers()` ohne Abfrage auf, um alle Instanzen zurückzugeben, oder verwende `getServersByGroup("lobby")` als Kurzform für einen Gruppennamen. Listenmethoden geben eine leere Liste zurück, wenn nichts übereinstimmt.

## Einzelnen Server suchen

Suche eine Instanz anhand ihrer eindeutigen ID oder anhand ihres Gruppennamens und ihrer numerischen ID:

```java
api.server().getServerById("server-uuid")
    .thenAccept(server -> System.out.println(server.getState()));

api.server().getServerByNumericalId("lobby", 1)
    .thenAccept(server -> System.out.println(server.getServerId()));
```

Das zurückgegebene Future schlägt fehl, wenn kein passender Server vorhanden ist.

### Aktuellen Server abrufen

Code, der innerhalb eines von SimpleCloud verwalteten Servers ausgeführt wird, kann seine eigene Instanz ermitteln:

```java
api.server().getCurrentServer()
    .thenAccept(server -> System.out.println(server.getServerId()));
```

`getCurrentServer()` verwendet die Umgebungsvariable `SIMPLECLOUD_UNIQUE_ID`. Das zurückgegebene Future schlägt fehl, wenn der aktuelle Prozess keiner Instanz zugeordnet ist.

## Auf die zugehörige Konfiguration zugreifen

Jede Instanz gehört entweder zu einer Gruppe oder zu einem persistenten Server. `getServerBase()` stellt deren gemeinsame Konfiguration bereit; `getGroup()` und `getPersistentServer()` geben Zugriff auf quellenspezifische Felder.

```java
api.server().getServerById("server-uuid")
    .thenAccept(server -> {
        if (server.isFromGroup()) {
            System.out.println("Gruppe: " + server.getGroup().getName());
        } else {
            System.out.println(
                "Persistent server: " +
                server.getPersistentServer().getName()
            );
        }

        System.out.println(
            "Configured slots: " + server.getServerBase().getMaxPlayers()
        );
    });
```

Für eine Instanz ist nur eine der Methoden `getGroup()` und `getPersistentServer()` verfügbar. Vermeide die veraltete Methode `getServerGroup()`, die bei Instanzen persistenter Server eine Exception auslöst.

## Instanz aktualisieren

`UpdateServerRequest` ändert nur die von dir festgelegten Felder:

```java
UpdateServerRequest update = UpdateServerRequest.builder()
    .maxPlayers(64)
    .maxMemory(2048)
    .build();

api.server().updateServer("server-uuid", update)
    .thenAccept(server ->
        System.out.println("Aktualisierte Plätze: " + server.getMaxPlayers()));
```

Der Builder unterstützt `state`, `properties`, `minMemory`, `maxMemory` und `maxPlayers`. Änderungen gelten für diese Instanz, nicht für ihre zugehörige Konfiguration. `playerCount` ist eine Laufzeit-Beobachtung, die vom Serverhost gemeldet wird, und ist über die HTTP-API schreibgeschützt; wird das Feld in einer Update-Anfrage gesendet, weist die API es als unbekanntes Feld ab. Die Plattform meldet normalerweise `state`; lege diesen Wert nur fest, wenn deine Integration für diese Meldung zuständig ist.

## Instanzeigenschaften verwalten

Eigenschaften verknüpfen Anwendungsdaten mit einer einzelnen Instanz. Aktualisierungen werden mit der vorhandenen Map zusammengeführt.

```java
api.server().updateServerProperties(
    "server-uuid",
    Map.of("gameMode", "competitive", "map", "castle")
);

api.server().deleteServerProperty("server-uuid", "map");
```

Verwende `updateServerProperty`, um einen einzelnen Schlüssel festzulegen, und `deleteServerProperties`, um mehrere Schlüssel zu entfernen. Jede Methode gibt die daraus resultierende Eigenschafts-Map zurück.

## Instanz stoppen

```java
api.server().stopServer("server-uuid")
    .thenRun(() -> System.out.println("Stopp eingeleitet"));
```

Das Future wird abgeschlossen, wenn SimpleCloud den Stopp einleitet, nicht erst nach Abschluss der Bereinigung. Verwende [Events für Serverzustände](/de/developer/api/events), wenn dein Plugin die späteren Übergänge im Lebenszyklus beobachten muss.

<Warning>
  Das Stoppen einer Instanz deaktiviert weder ihre Gruppe noch ihren persistenten Server. SimpleCloud kann eine Ersatzinstanz erstellen, um die Quellkonfiguration einzuhalten. Ändere diese Konfiguration zuerst, wenn der Server offline bleiben muss.
</Warning>

## Serverzustände

| Zustand | Bedeutung |
| --- | --- |
| `UNKNOWN_STATE` | Unbekannt oder nicht angegeben. |
| `PREPARING` | SimpleCloud bereitet die Instanz vor. |
| `STARTING` | Der Serverprozess wird gestartet. |
| `AVAILABLE` | Bereit, Verbindungen anzunehmen. |
| `INGAME` | Wird mit aktiven Spielern ausgeführt. |
| `STOPPING` | Das Herunterfahren läuft. |
| `CLEANUP` | Der Prozess wurde beendet und die Bereinigung läuft. |
