Mit Events kannst du auf Änderungen an Ressourcen in deinem SimpleCloud-Netzwerk reagieren. Abonniere sie über `api.event()` und verwende im Callback die stabile Ressourcen-ID des Events:

<Note>
  Die Ausschnitte auf dieser Referenzseite zeigen einzelne API-Aufrufe. Sie verwenden `api` für den unter [Installation](/de/developer/installation) erzeugten gemeinsamen `CloudApi`-Client und gehören in die Methoden deines Plugins.
</Note>

```java
Subscription subscription = api.event().server().onStateChanged(event -> {
    String serverId = event.getServerId();
    // React to the state change.
});
```

Bewahre die zurückgegebene `Subscription` auf und schließe sie, wenn dein Plugin beendet wird. Der [Leitfaden zur Event-Verarbeitung](/de/developer/guides/event-handling) zeigt den vollständigen Plugin-Lebenszyklus und wie du aus einem Callback sicher mit deiner Serverplattform interagierst.

## Event-Kategorie auswählen

| Kategorie | Abonnementmethoden | Callback-Typen |
| --- | --- | --- |
| `group()` | `onCreated`, `onUpdated`, `onDeleted` | `GroupCreatedEvent`, `GroupUpdatedEvent`, `GroupDeletedEvent` |
| `server()` | `onStarted`, `onStopped`, `onStateChanged`, `onUpdated`, `onDeleted` | `ServerStartedEvent`, `ServerStoppedEvent`, `ServerStateChangedEvent`, `ServerUpdatedEvent`, `ServerDeletedEvent` |
| `persistentServer()` | `onCreated`, `onStarted`, `onStopped`, `onUpdated`, `onDeleted` | `PersistentServerCreatedEvent`, `PersistentServerStartedEvent`, `PersistentServerStoppedEvent`, `PersistentServerUpdatedEvent`, `PersistentServerDeletedEvent` |
| `blueprint()` | `onCreated`, `onUpdated`, `onDeleted` | `BlueprintCreatedEvent`, `BlueprintUpdatedEvent`, `BlueprintDeletedEvent` |

Server-Events beschreiben einzelne Serverinstanzen. Events für persistente Server beschreiben Änderungen am persistenten Server selbst, etwa wenn er aktualisiert wird oder eine Serverinstanz startet.

## Zustand korrekt halten

Events informieren dich über eine Änderung; die Abfrage-APIs liefern den aktuellen Zustand. Abonnements empfangen nur Live-Events. Frage die Ressource daher beim Start deines Plugins ab oder wenn ein verpasstes Event zu einem falschen Zustand führen würde.

Schließe jedes Abonnement, sobald du es nicht mehr benötigst. Sowohl `close()` als auch `unsubscribe()` beenden die zukünftige Zustellung und können mehrfach aufgerufen werden.

## Callback-Daten auslesen

Jeder Callback stellt `getNetworkId()` und über `getTimestamp()` einen Zeitstempel im ISO-8601-Format bereit. Die übrigen Getter hängen vom Event-Typ ab.

Verwende zur Identifizierung einer Ressource bevorzugt den Getter für ihre stabile ID. Manche Event-Payloads enthalten kein eingebettetes Modell. In diesem Fall werfen Modell-Getter wie `getServer()`, `getGroup()` und `getBlueprint()` eine `IllegalStateException`. Frage die passende Ressourcen-API ab, wenn du aktuelle Daten benötigst.
