---
title: 'Persistent Servers API'
description: 'Erstelle, suche, aktualisiere und lösche persistente Server'
---

Ein persistenter Server ist eine einzelne langlebige Serverkonfiguration, zum Beispiel ein Survival-Server. Anders als eine Gruppe skaliert er nicht auf mehrere Instanzen.

Mit `api.persistentServer()` kannst du persistente Server erstellen und verwalten.

## Persistenten Server erstellen

Dieses Beispiel erstellt `survival-1` mit einem neuen Paper-Blueprint. Da der persistente Server aktiv ist, startet SimpleCloud seine Instanz und ersetzt sie, nachdem sie gestoppt wurde.

```java
CreatePersistentServerRequest request = CreatePersistentServerRequest.builder()
    .name("survival-1")
    .type(GroupServerType.SERVER)
    .minMemory(2048)
    .maxMemory(4096)
    .maxPlayers(80)
    .createBlueprint(CreateBlueprintRequest.builder()
        .configurator("paper")
        .serverSoftware("paper")
        .minecraftVersion("1.21.11")
        .build())
    .active(true)
    .serverhostId("serverhost-uuid")
    .tags(List.of("survival", "production"))
    .build();

api.persistentServer().createPersistentServer(request)
    .thenAccept(server -> System.out.println(
        "Created " + server.getName() + " with ID " + server.getPersistentServerId()));
```

Um stattdessen einen vorhandenen Blueprint zu verwenden, ersetze `createBlueprint(...)` durch eine Quelle:

```java
.source(SourceConfig.builder()
    .type(SourceType.BLUEPRINT)
    .blueprint("blueprint-uuid")
    .build())
```

Lege entweder `source` oder `createBlueprint` fest, nicht beides.

<Accordion title="Felder von CreatePersistentServerRequest">
  <ParamField body="name" type="string" required>
    Name des persistenten Servers. Bis zu 100 Zeichen aus ASCII-Buchstaben, Ziffern, Unterstrichen und Bindestrichen (`[A-Za-z0-9_-]`). Ein persistenter Server und eine Gruppe dürfen denselben Namen haben. ## Persistente Server suchen

Suche einen persistenten Server anhand seines Namens oder seiner ID:

```java
api.persistentServer().getPersistentServerByName("survival-1")
    .thenAccept(server -> System.out.println(server.getPersistentServerId()));

api.persistentServer().getPersistentServerById("persistent-server-uuid")
    .thenAccept(server -> System.out.println(server.getName()));
```

Beide Methoden werden mit einem Fehler abgeschlossen, wenn kein persistenter Server übereinstimmt. Bei der Suche nach Namen wird die Groß- und Kleinschreibung nicht berücksichtigt.

Verwende eine Abfrage, um die Liste zu filtern:

```java
PersistentServerQuery query = PersistentServerQuery.create()
    .filterByActive(true)
    .filterByTags("survival", "production")
    .limit(20);

api.persistentServer().getAllPersistentServers(query)
    .thenAccept(servers -> servers.forEach(server ->
        System.out.println(server.getName() + ": " + server.getPlayerCount())));
```

Die Abfrage kann nach Tags, Aktivierungszustand und Serverhost-ID filtern. Rufe `getAllPersistentServers()` ohne Abfrage auf, um alle persistenten Server zurückzugeben.

## Persistenten Server aktualisieren

Nur die in `UpdatePersistentServerRequest` festgelegten Felder werden geändert:

```java
UpdatePersistentServerRequest update = UpdatePersistentServerRequest.builder()
    .maxMemory(6144)
    .maxPlayers(100)
    .build();

api.persistentServer()
    .updatePersistentServer("persistent-server-uuid", update)
    .thenAccept(server -> System.out.println("Updated " + server.getName()));
```

Du kannst den Namen, Typ, Arbeitsspeicher, das Spielerlimit, den Aktivierungszustand, die Priorität, den zugewiesenen Serverhost, die Quelle, Workflows, Eigenschaften und Tags aktualisieren.

## Eigenschaften verwalten

Verwende die Eigenschaftsmethoden, um benutzerdefinierte Eigenschaften zu ändern, ohne die übrige Konfiguration zu aktualisieren:

```java
api.persistentServer().updatePersistentServerProperties(
    "persistent-server-uuid",
    Map.of("gameMode", "SURVIVAL", "region", "eu-central")
).thenAccept(properties -> System.out.println("Properties: " + properties));

api.persistentServer()
    .deletePersistentServerProperty("persistent-server-uuid", "region")
    .thenAccept(properties -> System.out.println("Properties: " + properties));
```

`updatePersistentServerProperties` führt die übergebenen Werte mit den vorhandenen Eigenschaften zusammen. Du kannst außerdem eine einzelne Eigenschaft aktualisieren oder mehrere Eigenschaften löschen.

## Persistenten Server löschen

```java
api.persistentServer()
    .deletePersistentServer("persistent-server-uuid")
    .thenRun(() -> System.out.println("Deleted persistent server"));
```

<Warning>
  Deaktiviere den persistenten Server zuerst, stoppe seine Instanz und lösche die Konfiguration, nachdem die Instanz beendet wurde. Ihre Dateien bleiben auf dem Serverhost erhalten.
</Warning>

## Felder von PersistentServer

`PersistentServer` erweitert `ServerBase` und stellt die folgenden Felder bereit.

<ResponseField name="persistentServerId" type="string" required>
  Eindeutige ID des persistenten Servers.
</ResponseField>

<ResponseField name="name" type="string" required>
  Name des persistenten Servers.
</ResponseField>

<ResponseField name="type" type="GroupServerType" required>
  `SERVER`, `PROXY` oder `UNKNOWN_SERVER`.
</ResponseField>

<ResponseField name="minMemory" type="integer | null">
  Minimaler Arbeitsspeicher in MB.
</ResponseField>

<ResponseField name="maxMemory" type="integer | null">
  Maximaler Arbeitsspeicher in MB.
</ResponseField>

<ResponseField name="maxPlayers" type="integer | null">
  Spielerlimit.
</ResponseField>

<ResponseField name="active" type="boolean | null">
  Legt fest, ob SimpleCloud eine Instanz in Betrieb halten soll.
</ResponseField>

<ResponseField name="priority" type="integer | null">
  Priorität des persistenten Servers.
</ResponseField>

<ResponseField name="serverhostId" type="string | null">
  ID des zugewiesenen Serverhosts.
</ResponseField>

<ResponseField name="playerCount" type="integer" required>
  Aktuelle Spieleranzahl oder `0`, wenn keine Instanz läuft.
</ResponseField>

<ResponseField name="source" type="SourceConfig | null">
  Blueprint- oder Container-Image-Quelle.
</ResponseField>

<ResponseField name="workflows" type="WorkflowsConfig | null">
  Lebenszyklus- und manuelle Workflows.
</ResponseField>

<ResponseField name="properties" type="Map<String, Object> | null">
  Benutzerdefinierte Eigenschaften.
</ResponseField>

<ResponseField name="tags" type="List<String> | null">
  Tags zum Filtern und Organisieren.
</ResponseField>

<ResponseField name="createdAt" type="string" required>
  Erstellungszeitpunkt im ISO-8601-Format.
</ResponseField>

<ResponseField name="updatedAt" type="string" required>
  Zeitpunkt der letzten Aktualisierung im ISO-8601-Format.
</ResponseField>

Verwende `api.server()`, um mit der laufenden Instanz zu arbeiten. Die Methode `getPersistentServerId()` verknüpft sie mit dieser Konfiguration.
