title: 'API für Gruppen'

Eine Gruppe beschreibt mehrere Server, die dieselbe Software, dieselben Ressourcen und dasselbe Skalierungsverhalten verwenden. Mit `api.group()` kannst du Gruppen verwalten oder einen weiteren Server für eine Gruppe anfordern.

<Note>
  Die Ausschnitte auf dieser Referenzseite zeigen einzelne API-Aufrufe. Sie verwenden `api` für den unter [Installation](/de/developer/installation) erzeugten gemeinsamen `CloudApi`-Client und gehören in die Methoden deines Plugins.
</Note>

## Gruppe erstellen

Dieses Beispiel erstellt eine Paper-Lobby-Gruppe und ihren Blueprint. SimpleCloud hält eine Lobby in Betrieb und kann die Gruppe auf bis zu drei Server skalieren. Dabei werden 20 verfügbare Spielerplätze vorgehalten.

```java
CreateGroupRequest request = CreateGroupRequest.builder()
    .name("lobby")
    .type(GroupServerType.SERVER)
    .minMemory(1024)
    .maxMemory(2048)
    .maxPlayers(100)
    .createBlueprint(CreateBlueprintRequest.builder()
        .configurator("paper")
        .serverSoftware("paper")
        .minecraftVersion("1.21.11")
        .build())
    .scaling(ScalingConfig.builder()
        .scalingMode(ScalingMode.SLOTS)
        .minServers(1)
        .maxServers(3)
        .availableSlots(20)
        .build())
    .build();

api.group().createGroup(request)
    .thenAccept(group -> System.out.println(
        "Gruppe " + group.getName() + " mit ID " + group.getServerGroupId() + " erstellt"
    ));
```

Der Gruppenname wird auch für den neuen Blueprint verwendet. Um stattdessen einen vorhandenen Blueprint zu verwenden, ersetze `createBlueprint(...)` durch:

```java
.source(SourceConfig.builder()
    .type(SourceType.BLUEPRINT)
    .blueprint("blueprint-uuid")
    .build())
```

Lege nicht gleichzeitig `createBlueprint` und einen vorhandenen Blueprint oder eine Image-Quelle fest.

<Accordion title="Felder von CreateGroupRequest">

## Gruppen suchen

Suche eine Gruppe anhand ihres Namens oder ihrer ID:

```java
api.group().getGroupByName("lobby")
    .thenAccept(group -> System.out.println(group.getServerGroupId()));

api.group().getGroupById("group-uuid")
    .thenAccept(group -> System.out.println(group.getName()));
```

Das zurückgegebene Future schlägt fehl, wenn die Gruppe nicht vorhanden ist. Bei der Suche nach Namen wird die Groß- und Kleinschreibung nicht berücksichtigt.

Verwende `GroupQuery`, um die Gruppenliste nach Typ, Tag oder Ergebnislimit zu filtern:

```java
GroupQuery query = GroupQuery.create()
    .filterByType(GroupServerType.SERVER)
    .filterByTag("production")
    .limit(25);

api.group().getAllGroups(query)
    .thenAccept(groups -> groups.forEach(group ->
        System.out.println(group.getName())
    ));
```

Rufe `getAllGroups()` ohne Abfrage auf, um alle Gruppen zurückzugeben.

## Gruppe aktualisieren

`UpdateGroupRequest` ändert nur die von dir festgelegten Felder:

```java
UpdateGroupRequest update = UpdateGroupRequest.builder()
    .maxPlayers(120)
    .build();

api.group().updateGroup("group-uuid", update)
    .thenAccept(group -> System.out.println("Gruppe " + group.getName() + " aktualisiert"));
```

Du kannst `name`, `type`, `minMemory`, `maxMemory`, `maxPlayers`, `active`, `priority`, `deployment`, `scaling`, `source`, `workflows`, `properties` und `tags` aktualisieren.

Gib beim Aktualisieren eines verschachtelten Objekts wie `ScalingConfig` alle Werte an, die es enthalten soll. Verwende die folgenden Methoden für Eigenschaften, wenn du nur einzelne Eigenschaften zusammenführen möchtest.

## Gruppeneigenschaften verwalten

Gruppeneigenschaften speichern benutzerdefinierte Daten für deine Plugins. Aktualisierungen werden mit der vorhandenen Map zusammengeführt.

```java
Map<String, Object> properties = Map.of(
    "gameMode", "ADVENTURE",
    "region", "eu-west"
);

api.group().updateGroupProperties("group-uuid", properties)
    .thenAccept(updated -> System.out.println("Eigenschaften: " + updated));

api.group().deleteGroupProperty("group-uuid", "region")
    .thenAccept(remaining -> System.out.println("Eigenschaften: " + remaining));
```

Verwende `deleteGroupProperties`, um mehrere Schlüssel gleichzeitig zu entfernen. Jede Eigenschaftsmethode gibt die daraus resultierende Map zurück.

## Weiteren Server starten

Fordere einen zusätzlichen Server an, wenn eine bestimmte Aktion deiner Anwendung eine weitere Instanz benötigt:

```java
api.group().getGroupByName("lobby")
    .thenCompose(api.group()::requestServerStart)
    .thenRun(() -> System.out.println("Serverstart angefordert"));
```

Dadurch wird eine einzelne Startanforderung in die Warteschlange gestellt, ohne die Skalierungskonfiguration der Gruppe zu ändern. Verwende die [Servers API](/de/developer/api/servers) oder Server-Events, wenn dein Plugin auf den neuen Server warten muss.

### Startwarteschlange prüfen

Die Warteschlange zeigt ausstehende und fehlgeschlagene manuelle Startanforderungen:

```java
api.group().getServerStartQueue()
    .thenAccept(queue -> {
        GroupStartQueueEntry lobby = queue.findByServerGroupName("lobby");
        if (lobby == null) {
            return;
        }

        lobby.getStarts().stream()
            .filter(start -> start.getStatus() == GroupStartQueueItemStatus.FAILED)
            .forEach(start -> System.err.println(start.getFailureReason()));
    });
```

`findByServerGroupId` und `findByServerGroupName` geben `null` zurück, wenn die Warteschlange keinen Eintrag für die Gruppe enthält.

Entferne ausstehende Startanforderungen für eine Gruppe mit:

```java
api.group().clearServerStartQueue("group-uuid");
```

Bereits erstellte Server werden dadurch nicht gestoppt.

<Accordion title="Felder der Startwarteschlange">
  `GroupStartQueue` enthält Gesamtwerte über alle Gruppen und eine Liste von `GroupStartQueueEntry`-Objekten.

  <ResponseField name="count" type="integer" required>
    Anzahl der Gruppeneinträge.
  </ResponseField>

  <ResponseField name="queuedStarts" type="integer" required>
    Anzahl der ausstehenden Starts.
  </ResponseField>

  <ResponseField name="failedStarts" type="integer" required>
    Anzahl der fehlgeschlagenen Starts.
  </ResponseField>

  <ResponseField name="totalStarts" type="integer" required>
    Gesamtanzahl der Startanforderungen.
  </ResponseField>

  <ResponseField name="items" type="List<GroupStartQueueEntry>" required>
    Nach Servergruppe gruppierte Warteschlangeneinträge.
  </ResponseField>

  Jeder `GroupStartQueueEntry` stellt die ID und den Namen der Gruppe, die Anzahl ihrer Starts sowie eine Liste `starts` bereit. Ein `GroupStartQueueItem` enthält seine ID, den Erstellungszeitpunkt, den Status und den Grund eines Fehlschlags. Der Status ist `PENDING`, `FAILED` oder `UNKNOWN`.
</Accordion>

## Gruppe löschen

```java
api.group().deleteGroup("group-uuid");
```

<Warning>
  Deaktiviere die Gruppe zuerst, damit sie gestoppte Instanzen nicht ersetzen kann. Stoppe ihre Server, warte, bis sie beendet wurden, und lösche anschließend die Gruppe.
</Warning>

<Accordion title="Felder von ScalingConfig">
  <ResponseField name="minServers" type="integer" required>
    Mindestanzahl der vorzuhaltenden Server.
  </ResponseField>

  <ResponseField name="maxServers" type="integer" required>
    Maximale Anzahl der Server, die die Gruppe erstellen darf.
  </ResponseField>

  <ResponseField name="scalingMode" type="ScalingMode | null">
    `SLOTS` entspricht dem Dashboard-Modus **Slots** und hält freie Kapazität vor. `PLAYERS` entspricht dem Dashboard-Modus **Servers** und startet Server anhand der Spielerauslastung.
  </ResponseField>

  <ResponseField name="availableSlots" type="integer" required>
    Anzahl der im Modus `SLOTS` vorzuhaltenden freien Spielerplätze.
  </ResponseField>

  <ResponseField name="playerThreshold" type="number" required>
    Schwellenwert der Spielerauslastung zwischen `0` und `1`.
  </ResponseField>

  <ResponseField name="scaleDown" type="ScaleDownConfig | null">
    Einstellungen zum Herunterskalieren.
  </ResponseField>

  <Note>
    `SLOTS` kann Server starten und stoppen. `PLAYERS` startet Server nur; zusätzliche Instanzen werden nicht automatisch gestoppt.
  </Note>
</Accordion>

## Gruppenservertypen

| Wert | Beschreibung |
| --- | --- |
| `SERVER` | Gameserver wie Paper oder Spigot |
| `PROXY` | Proxyserver wie Velocity oder BungeeCord |
| `UNKNOWN_SERVER` | Von der API zurückgegebener unbekannter Servertyp |
