## Auf verfügbare Server warten

Der Listener verwendet den `CloudApi`-Client, den dein Plugin bereits verwaltet, und benachrichtigt deinen Anwendungscode, sobald ein Server verfügbar wird:

```java ServerAvailabilityListener.java
package com.example;

import app.simplecloud.api.CloudApi;
import app.simplecloud.api.event.Subscription;
import app.simplecloud.api.server.ServerState;

public final class ServerAvailabilityListener implements AutoCloseable {
    private final Subscription subscription;

    public ServerAvailabilityListener(
        CloudApi cloudApi,
        Runnable onServerAvailable
    ) {
        subscription = cloudApi.event().server().onStateChanged(event -> {
            if (event.getNewState() == ServerState.AVAILABLE) {
                onServerAvailable.run();
            }
        });
    }

    @Override
    public void close() {
        subscription.close();
    }
}
```

Erstelle den Listener beim Start deines Plugins und verknüpfe ihn mit der Arbeit, die auf einen verfügbaren Server wartet:

```java
serverAvailability = new ServerAvailabilityListener(
    cloudApi,
    () -> matchmaking.refreshAvailableServers()
);
```

Behandle den Callback als Signal, wartende Arbeit erneut zu versuchen oder die deinem Routing-System bekannten Ziele zu aktualisieren.

<Note>
Events melden nur Änderungen, die nach dem Abonnieren eintreten. Wenn dein Plugin beim Start auch den aktuellen Zustand benötigt, rufe ihn separat über die [Servers API](/de/developer/api/servers) ab.
</Note>

Wenn der Callback den Zustand von Bukkit, Folia, Velocity oder BungeeCord verändert, plane diese plattformspezifische Arbeit über den Scheduler der jeweiligen Plattform ein.

## Listener schließen

Schließe den Listener beim Beenden deines Plugins, bevor du den gemeinsam verwendeten `CloudApi`-Client schließt:

```java
if (serverAvailability != null) {
    serverAvailability.close();
}
```

Damit werden zukünftige Callbacks beendet. Der Listener schließt den gemeinsam verwendeten `CloudApi`-Client nicht.

In der [Referenz zur Events API](/de/developer/api/events) findest du die weiteren Event-Kategorien und Callback-Typen.
