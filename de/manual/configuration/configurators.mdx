Vor jedem Serverstart schreibt ein Configurator Werte wie den zugewiesenen Port und das Spielerlimit in die Konfigurationsdateien der Serversoftware. Wenn du eine Gruppe oder einen persistenten Server erstellst, wählt das Dashboard einen eingebauten Configurator aus. Für die Standardkonfiguration musst du nichts weiter einrichten.

Erstelle einen eigenen Configurator, wenn du Einstellungen hinzufügen möchtest, die der eingebaute Configurator nicht verwaltet. Verwende stattdessen [Templates](/de/manual/setup/templates), wenn du nur dieselben Dateien auf deine Server kopieren möchtest.

<Warning>
  Ein eigener Configurator ersetzt den ausgewählten eingebauten Configurator. Übernimm daraus alle Einstellungen, die dein Server benötigt. Dazu gehören insbesondere der Port und die Proxy-Einstellungen.
</Warning>

## Eigenen Configurator erstellen

Dieses Beispiel erweitert den Configurator **Paper/Spigot Standalone** um den Schwierigkeitsgrad und die Sichtweite. Wenn dein Server über einen Proxy verbunden wird, beginne stattdessen mit dem passenden Proxy-Configurator.

<Steps>
  <Step title="Configurator-Datei erstellen">
    Erstelle auf dem Serverhost die Datei `options/configurators/paper_survival.yml`:

    ```yaml options/configurators/paper_survival.yml
    paths:
      - path: "server.properties"
        type: "PROPERTIES"
        data:
          server-ip: "0.0.0.0"
          server-port: %port%
          max-players: %max-players%
          online-mode: true
          difficulty: "hard"
          view-distance: 10
    ```

    Jeder Wert unter `path` verweist auf eine Datei relativ zum jeweiligen Serververzeichnis. Ein Configurator kann mehrere `path`-Einträge enthalten und damit mehrere Dateien ändern.
  </Step>

  <Step title="Configurator auswählen">
    Öffne die Gruppe oder den persistenten Server im Dashboard und gehe zu **Settings > Blueprint**. Wähle unter **Software Configuration** die Option **Custom**, gib `paper_survival` ein und speichere die Änderung.
  </Step>

  <Step title="Änderungen anwenden">
    Starte die Gruppe oder den persistenten Server neu. SimpleCloud wendet den Configurator vor dem Start auf jeden Server an, der diesen Blueprint verwendet.
  </Step>
</Steps>

<Warning>
  Wenn der Server auf mehreren Serverhosts ausgeführt werden kann, füge die Configurator-Datei jedem dieser Serverhosts hinzu.
</Warning>

## Configurator-Referenz

Jeder Eintrag unter `paths` gibt eine Konfigurationsdatei, ihr Format und die anzuwendenden Werte an.

<AccordionGroup>
  <Accordion title="Unterstützte Dateitypen">
    | Typ | Dateiformat |
    | --- | --- |
    | `YML` | YAML |
    | `JSON` | JSON |
    | `TOML` | TOML |
    | `PROPERTIES` | Java-Properties |
    | `TXT` | Textdatei |

    Strukturierte Dateien behalten Werte bei, die nicht im Configurator angegeben sind. `TXT` ersetzt die gesamte Datei.
  </Accordion>

  <Accordion title="Verfügbare Platzhalter">
    Verwende Platzhalter, wenn ein Wert von der Serverinstanz abhängt.

    | Platzhalter | Wert |
    | --- | --- |
    | `%port%` | Zugewiesener Port |
    | `%group%` | Name der Gruppe oder des persistenten Servers |
    | `%numerical-id%` | Instanznummer |
    | `%type%` | Server- oder Proxy-Typ |
    | `%min-memory%` | Minimaler Arbeitsspeicher in MB |
    | `%max-memory%` | Maximaler Arbeitsspeicher in MB |
    | `%max-players%` | Spielerlimit |
    | `%forwarding-secret%` | Forwarding-Secret des Proxys |
    | `%velocity-config-version%` | Velocity-Konfigurationsversion |

    Setze Platzhalter in Anführungszeichen, wenn ihr Ergebnis Text sein muss:

    ```yaml
    server-name: "%group%"
    server-port: %port%
    ```

    Eigene Properties der Gruppe oder des persistenten Servers stehen ebenfalls als Platzhalter zur Verfügung. Eine Property namens `motd` kannst du beispielsweise als `%motd%` verwenden.

    Verwende eine [Secret-Referenz](/de/manual/configuration/secrets) als Configurator-Wert, um ein Passwort, Token oder einen anderen vertraulichen Wert einzusetzen:

    ```yaml
    password: "{{ secrets.DATABASE_PASSWORD }}"
    ```
  </Accordion>
</AccordionGroup>

## Fehlerbehebung

<AccordionGroup>
  <Accordion title="Der Configurator wird nicht gefunden">
    Prüfe, ob `options/configurators/{name}.yml` auf jedem Serverhost vorhanden ist, auf dem der Server ausgeführt werden kann. Der im Dashboard angegebene eigene Name muss dem Dateinamen ohne `.yml` entsprechen.
  </Accordion>

  <Accordion title="Eine Einstellung ändert sich nicht">
    Starte zuerst den Server neu. Wenn sich der Wert weiterhin nicht ändert, prüfe, ob `path` relativ zum Serververzeichnis ist, `type` dem Dateiformat entspricht und die Einstellung korrekt unter `data` eingerückt ist.
  </Accordion>

  <Accordion title="Ein Platzhalter bleibt in der Datei stehen">
    Prüfe die Schreibweise des Platzhalters und verwende die Prozent-Syntax, zum Beispiel `%port%`. Füge für einen eigenen Platzhalter der Gruppe oder dem persistenten Server eine Property mit demselben Namen hinzu.
  </Accordion>

  <Accordion title="Der Server startet nach Auswahl des Configurators nicht">
    Prüfe das Serverhost-Log auf einen Configurator-Fehler. Häufige Ursachen sind ungültiges YAML, ein nicht unterstützter `type` oder ein Wert, dessen Struktur nicht zur Zieldatei passt.
  </Accordion>
</AccordionGroup>
