Eine Servergruppe erstellt austauschbare Server aus einer gemeinsamen Konfiguration. Verwende eine Gruppe, wenn du mehrere identische Server benötigst oder SimpleCloud die Serveranzahl automatisch für dich anpassen soll.

| Verwende eine Gruppe für | Verwende einen persistenten Server für |
| --- | --- |
| Proxys, Lobbys und Minigames | SMP-, Citybuild- und Build-Server |
| Server, die jederzeit ersetzt werden können | Einen Server, der seine Welt oder andere lokale Dateien behalten muss |
| Mehrere Server mit derselben Einrichtung | Einen einzelnen, langfristig betriebenen Server |

Wenn die rechte Spalte zu deinem Vorhaben passt, lies den Abschnitt [Persistente Server](/de/manual/setup/persistent-servers).

[Verbinde mindestens einen Serverhost](/de/manual/setup/installation) mit deinem Netzwerk, bevor du beginnst.

## Gruppentyp auswählen

| Typ | Verwende ihn für | Beispiele |
| --- | --- | --- |
| **Server** | Gameserver, denen Spieler beitreten | Paper, Purpur, Spigot, Fabric |
| **Proxy** | Proxys, die Spieler an Gameserver weiterleiten | Velocity, BungeeCord |

## Servergruppe erstellen

<Steps>
  <Step title="Erstellungsseite öffnen">
    Öffne im Dashboard **Server Groups** und klicke auf **Add Group**.
  </Step>

  <Step title="Typ und Namen auswählen">
    Wähle **Server** oder **Proxy** aus und gib anschließend einen eindeutigen Namen ein. Namen dürfen bis zu 100 ASCII-Buchstaben, Ziffern, Unterstriche und Bindestriche (`[A-Za-z0-9_-]`) enthalten. Bei der Eindeutigkeit innerhalb des Netzwerks wird nicht zwischen Groß- und Kleinschreibung unterschieden – `Lobby` und `lobby` gelten als derselbe Name.

    Aktiviere **Activate on creation**, wenn SimpleCloud die Gruppe sofort starten soll.
  </Step>

  <Step title="Software auswählen">
    Wähle die Serversoftware und die verfügbaren Versionsoptionen aus.

    Wenn die Software nicht aufgeführt ist, wähle **Custom** und fülle die erforderlichen Felder aus.
  </Step>

  <Step title="Ressourcen festlegen">
    Wähle das Spielerlimit und den Arbeitsspeicher pro Server aus. Stelle sicher, dass deine Serverhosts über genügend Arbeitsspeicher für die Anzahl der geplanten Server verfügen.

    Gib für eine Proxy-Gruppe außerdem ihren Startport ein.
  </Step>

  <Step title="Gruppe erstellen">
    Prüfe die Konfiguration, füge benötigte Plugins hinzu und klicke auf **Create Group**.
  </Step>
</Steps>

## Gruppe aktivieren oder deaktivieren

Eine aktive Gruppe startet und stoppt Server entsprechend ihrer Skalierungskonfiguration. Eine inaktive Gruppe führt keine Server aus.

**Activate on creation** ist standardmäßig aktiviert. Öffne nach dem Erstellen der Gruppe ihren Tab **Servers**, um den ersten Server beim Start zu verfolgen. Später kannst du die Gruppe über ihr Aktionsmenü aktivieren oder deaktivieren.

## Skalierung konfigurieren

Die Skalierung steuert, wie viele Server SimpleCloud bereithält. Öffne die Gruppe und gehe anschließend zu **Settings > Scaling**.

Für beide Modi gelten diese Grenzen:

- **Minimum Servers** ist die grundlegende Anzahl an Servern, die von der Gruppe ausgeführt werden.
- **Maximum Servers** ist die höchste Anzahl an Servern, welche die Gruppe ausführen darf.

Wähle anschließend den Modus aus, der zum gewünschten Wachstum der Gruppe passt.

### Nach Spielerplätzen skalieren

Wähle **Slots**, wenn SimpleCloud die Anzahl der Server anhand der Spielerkapazität anpassen soll. Lege unter **Available Slots** fest, wie viele freie Spielerplätze du in der gesamten Gruppe vorhalten möchtest.

SimpleCloud startet Server, wenn mehr Kapazität benötigt wird, und stoppt ungenutzte Server, sobald genügend Kapazität verbleibt. Die Anzahl bleibt immer zwischen deinem Minimum und Maximum.

Wenn beispielsweise jeder Server 100 Spieler zulässt und **Available Slots** auf `50` gesetzt ist, startet SimpleCloud einen weiteren Server, sobald die Gruppe weniger als 50 freie Spielerplätze hat.

<Warning>
  **Idle Time** verzögert die Abwärtsskalierung derzeit nicht. SimpleCloud kann einen ungenutzten Server stoppen, sobald die Gruppe genügend freie Kapazität hat.
</Warning>

### Nach verfügbaren Servern skalieren

Wähle **Servers**, wenn eine bestimmte Anzahl an Servern für Spieler bereitstehen soll. **Player Threshold** legt fest, ab welcher Auslastung ein Server nicht mehr als bereit gilt.

Wenn **Minimum Servers** beispielsweise auf `2` und **Player Threshold** auf `0.75` gesetzt ist, hält SimpleCloud nach Möglichkeit zwei Server unter 75 % Auslastung bereit. Wenn sich diese Server füllen, startet SimpleCloud bis zum Wert unter **Maximum Servers** weitere Server.

<Note>
  Der Modus **Servers** startet Server nur. Zusätzliche Server werden nicht automatisch gestoppt. Wähle **Slots**, wenn die Gruppe auch abwärts skalieren soll.
</Note>

Speichere deine Änderungen und beobachte anschließend im Tab **Servers**, wie sich die Gruppe an die neue Kapazität annähert.

## Festlegen, wo Server laufen

Öffne **Settings > Deployment**, um auszuwählen, welche Serverhosts die Gruppe ausführen dürfen. Lasse alle Serverhosts aktiviert, sofern die Gruppe nicht auf bestimmten Maschinen laufen muss.

Wenn du nur einige Serverhosts aktivierst, ziehe sie in die Reihenfolge, in der SimpleCloud sie bevorzugen soll. SimpleCloud kann einen anderen aktivierten Serverhost verwenden, wenn ein bevorzugter Host keine Kapazität hat.

Wenn du alle Serverhosts deaktivierst, kann SimpleCloud keinen neuen Server für die Gruppe starten.

## Gruppenänderungen anwenden

Änderungen an Software, Plugins oder Serverdateien werden angewendet, wenn neue Server starten. Öffne nach dem Speichern einer Änderung das Aktionsmenü der Gruppe und verwende **Hold to rolling restart**, um sie auf laufende Server anzuwenden.

Bei einem Rolling Restart werden die Server der Gruppe nacheinander ersetzt, sodass während der Änderung Kapazität verfügbar bleibt. **Restart all** stoppt die aktuellen Server gemeinsam. Wenn du die Gruppe deaktivierst, werden sie gestoppt, ohne dass Ersatz gestartet wird.

<Warning>
  Dateien, die nur innerhalb eines Gruppenservers gespeichert sind, sind temporär. Verwende für Daten, die einen Austausch überdauern müssen, einen persistenten Server.
</Warning>

## Fehlerbehebung

<AccordionGroup>
  <Accordion title="Kein Server startet">
    Stelle sicher, dass die Gruppe aktiv ist, **Minimum Servers** mindestens `1` beträgt und mindestens ein aktivierter Serverhost online ist und über genügend freien Arbeitsspeicher verfügt.
  </Accordion>

  <Accordion title="Ein Server schließt den Start nicht ab">
    Öffne die Logs des betroffenen Servers und die Serverhost-Logs. Dort erkennst du, ob die Softwareeinrichtung, ein Workflow oder der Serverprozess fehlgeschlagen ist.
  </Accordion>

  <Accordion title="Die Gruppe skaliert nicht wie erwartet">
    Prüfe **Minimum Servers**, **Maximum Servers** und die Einstellung des verwendeten Modus: **Available Slots** für den Modus Slots oder **Player Threshold** für den Modus Servers. Beachte, dass nur der Modus Slots zusätzliche Server automatisch stoppt.
  </Accordion>
</AccordionGroup>
