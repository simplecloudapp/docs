## Von der Konfiguration zum laufenden Server

Wenn du eine Gruppe aktivierst, ihre Skalierungseinstellungen änderst oder einen persistenten Server startest:

1. Der Controller ermittelt, welche Server laufen sollen.
2. Er wählt einen zulässigen Serverhost mit ausreichenden Ressourcen aus.
3. Der Serverhost bereitet den Minecraft-Server vor und führt ihn aus.
4. Status, Logs und Ressourcennutzung werden im Dashboard und in der CLI verfügbar.

Über das Dashboard oder die [CLI](/de/manual/introduction/architecture/cli) legst du fest, was ausgeführt werden soll. Der Controller verwaltet den Zustand deiner Servergruppen, persistenten Server und verbundenen [Serverhosts](/de/manual/introduction/architecture/serverhost).

Er hält das Dashboard und die CLI auf dem Laufenden.

Danach hält der Controller den von dir konfigurierten Zustand aufrecht. Er startet beispielsweise einen weiteren Gruppenserver, wenn Spieler mehr Kapazität benötigen. Einen manuell gestoppten Gruppenserver kann er ersetzen, solange die Skalierungseinstellungen der Gruppe diesen Server weiterhin erfordern.

<Note>
  Der Controller koordiniert Minecraft-Server, führt sie aber nicht selbst aus. Deine Serverhosts stellen die Maschinen und Ressourcen bereit, auf denen sie laufen.
</Note>

## Was das für dich bedeutet

Im täglichen Betrieb musst du den Controller nicht separat verwalten.

Wenn ein Server nicht startet, prüfe zuerst, ob ein zulässiger Serverhost online ist und genügend freien Arbeitsspeicher hat. Öffne anschließend die Server- oder Serverhost-Logs, um zu erkennen, ob die Vorbereitung oder der Minecraft-Prozess fehlgeschlagen ist.
