## Plugin installieren

<Steps>
  <Step title="Plugin installieren">
    Lade Proxy Essentials von [GitHub](https://github.com/simplecloudapp/simplecloud-plugins/releases) oder [Modrinth](https://modrinth.com/organization/simplecloud) herunter und lege die JAR in den Ordner `plugins/` des Proxy Templates.
  </Step>

  <Step title="Proxy starten">
    Starte einen Proxy. Proxy Essentials erstellt seine Dateien in `plugins/simplecloud-proxy-essentials/`.
  </Step>

  <Step title="Plugin prüfen">
    Füge den Proxy zu deiner Minecraft Serverliste hinzu.

    <Check>
      Die Serverliste zeigt die MOTD und das Icon von SimpleCloud.
    </Check>
  </Step>
</Steps>

Damit deine Änderungen erhalten bleiben, kopiere den Ordner `plugins/simplecloud-proxy-essentials/` ins Proxy Template. Dateien, die nur auf einem laufenden Proxy einer Gruppe liegen, werden beim Stoppen gelöscht. Mehr dazu unter [Templates](/de/manual/setup/templates).

## Dateien

| Datei | Beschreibung |
| ----- | ------------ |
| `config.yml` | Join States, Domains, Whitelist, Spielerzahl, Tablist und Kick Verhalten |
| `messages.yml` | Nachrichten, Datumsformate und Ping Farben |
| `layout/*.yml` | Layouts für die Serverliste mit MOTD, Icon, Hover Text, Version und Slots |
| `layout/server-icons/` | Server Icons für die Layouts |

## Join States

Ein Join State legt fest, wer joinen darf. Du definierst Join States in der `config.yml` und setzt sie auf eine Gruppe, einen einzelnen Server oder einen persistenten Server.

```yaml config.yml
initial-state: public
initial-layout: public

joinstates:
  - name: public
    permission:
      join: ''
      full: 'simplecloud.proxy-essentials.join.full.public'
    forced-motd-layout: null
  - name: maintenance
    permission:
      join: 'simplecloud.proxy-essentials.join.maintenance'
      full: 'simplecloud.proxy-essentials.join.maintenance'
    forced-motd-layout: maintenance
```

| Einstellung | Beschreibung |
| ----------- | ------------ |
| `name` | Name des Join States |
| `permission.join` | Berechtigung zum Joinen. Leer lassen, damit alle joinen dürfen |
| `permission.full` | Berechtigung zum Joinen, wenn die Proxygruppe voll ist |
| `forced-motd-layout` | Layout, das angezeigt wird, solange der Join State auf dem Proxy aktiv ist. `null` zeigt das normale Layout |
| `initial-state` | Join State für Ziele, die noch keinen haben |
| `initial-layout` | Layout, wenn kein anderes Layout passt |

### Proxy und Backend Server

Wo du einen Join State setzt, ändert seine Wirkung:

| Ziel | Wirkung |
| ---- | ------- |
| Proxygruppe, zum Beispiel `Proxy` | Legt fest, wer das Netzwerk betreten darf, und kann die MOTD ändern |
| Backend Gruppe, zum Beispiel `Lobby` | Legt fest, wer auf die Server dieser Gruppe darf |
| Einzelner Server, zum Beispiel `Lobby-1` | Gilt nur für diesen Server |
| Persistenter Server, zum Beispiel `Citybuild` | Gilt nur für diesen persistenten Server |

<Info>
  Wenn du `Lobby` in den Wartungsmodus setzt, ändert sich die MOTD nicht. Um das ganze Netzwerk in den Wartungsmodus zu setzen, ändere den Join State der **Proxygruppe**.
</Info>

### Wartungsmodus aktivieren

Wenn deine Proxygruppe `Proxy` heißt:

<Steps>
  <Step title="Join State setzen">
    ```text
    /scproxy joinstate set group Proxy maintenance
    ```

    Der Join State wird auf der Gruppe und allen laufenden Servern gespeichert. Neue Server der Gruppe starten ebenfalls damit.
  </Step>

  <Step title="Join State prüfen">
    ```text
    /scproxy joinstate info group Proxy
    ```

    Spieler brauchen jetzt `simplecloud.proxy-essentials.join.maintenance`, um zu joinen. Aktualisiere deine Serverliste, um die MOTD für den Wartungsmodus zu sehen.
  </Step>

  <Step title="Netzwerk wieder öffnen">
    ```text
    /scproxy joinstate set group Proxy public
    ```
  </Step>
</Steps>

Weitere Beispiele:

```text
/scproxy joinstate set group Lobby maintenance
/scproxy joinstate set group Lobby maintenance 1
/scproxy joinstate set ps Citybuild maintenance
```

Der erste Befehl ändert die ganze Gruppe `Lobby`. Der zweite ändert nur `Lobby-1`. Der dritte ändert den persistenten Server `Citybuild`.

### Server außerhalb von SimpleCloud

Server, die nicht von SimpleCloud verwaltet werden, verwenden `initial-state`. Um ihnen einen anderen Join State zu geben, trage sie mit ihrem Namen ein:

```yaml config.yml
external-server-joinstates:
  queue-limbo: public
```

### Whitelist

Spieler auf der Whitelist können immer joinen, auch im Wartungsmodus oder wenn das Netzwerk voll ist.

```yaml config.yml
whitelist:
  enabled: true
  players:
    - Notch
    - 069a79f4-44e9-4726-a5be-fca90e38aaf5
```

Du kannst Spielernamen oder UUIDs verwenden. Nutze die Whitelist nur für Admins oder im Notfall. Für alle anderen solltest du Berechtigungen verwenden.

## Layouts für die Serverliste

Jede Datei in `layout/` ist ein Layout. Der Dateiname ist der Name des Layouts, `layout/maintenance.yml` ist also das Layout `maintenance`.

```yaml layout/public.yml
config-version: '2'

motd:
  enabled: true
  update-type: RANDOM # RANDOM oder QUEUE
  # update-time: 100
  layouts:
    - name: public
      line1: '<center><color:#0ea5e9>A simplecloud.app network</center>'
      line2: ' '

server-icon:
  enabled: true
  file: simplecloud.png

player-list:
  enabled: true
  player-list:
    - ''
    - 'simplecloud.app'
    - ''

version:
  name:
    enabled: false
    text: Example
  slots:
    enabled: true
    type: REAL # REAL, FAKE oder DYNAMIC
    fake-slots: 100
    dynamic-player-range: 5
```

| Einstellung | Beschreibung |
| ----------- | ------------ |
| `motd.layouts` | MOTD Einträge mit jeweils zwei Zeilen |
| `motd.update-type` | `RANDOM` wählt einen zufälligen Eintrag, `QUEUE` zeigt die Einträge nacheinander |
| `motd.update-time` | Zeit in Ticks bis zum nächsten Eintrag. Ohne diese Einstellung wechselt der Eintrag bei jedem Ping. `0` zeigt immer den ersten Eintrag |
| `<center>` | Zentriert eine Zeile in der Serverliste |
| `server-icon.file` | Icon aus `layout/server-icons/` |
| `player-list` | Text, der beim Hovern über die Spielerzahl angezeigt wird |
| `version.name` | Text, der statt der Spielerzahl angezeigt wird |
| `version.slots.type` | `REAL` zeigt die echten maximalen Spieler, `FAKE` zeigt `fake-slots`, `DYNAMIC` zeigt die Online Spieler plus `dynamic-player-range` |

### Welches Layout angezeigt wird

Der Proxy verwendet das erste Layout, das existiert:

1. Das Layout einer passenden [Domain](#motd-nach-domain)
2. Das `forced-motd-layout` des aktiven Join States auf dem Proxy
3. Das Layout, das mit `/scproxy layout set` gesetzt wurde
4. `initial-layout`

Um ein Layout auf einer Gruppe zu setzen, verwende:

```text
/scproxy layout set Proxy public
```

## MOTD nach Domain

Zeige ein anderes Layout je nachdem, mit welcher Domain Spieler joinen, zum Beispiel wenn mehrere Domains auf denselben Proxy zeigen.

```yaml config.yml
domains:
  - domain: play.example.com
    target: Lobby
    rules:
      - state: public
        layout: lobby-public
      - state: maintenance
        layout: lobby-maintenance

  - domain: citybuild.example.com
    target: Citybuild
    rules:
      - state: public
        layout: citybuild
```

| Einstellung | Beschreibung |
| ----------- | ------------ |
| `domain` | Vollständige Domain, zum Beispiel `play.example.com`. Wildcards werden nicht unterstützt |
| `target` | Gruppe oder persistenter Server, dessen Join State das Layout bestimmt |
| `rules` | Layout für jeden Join State des Ziels |

Wenn keine Regel zum Join State des Ziels passt, verwendet der Proxy dessen `forced-motd-layout` und danach `initial-layout`. Wenn keine Domain passt, gilt die normale [Reihenfolge](#welches-layout-angezeigt-wird).

<Info>
  Das ändert nur die MOTD. Um Spieler einer Domain auch auf einen bestimmten Server zu schicken, verwende die [Subdomain Routen](/de/manual/plugin/server-connection#subdomain-routen) von Server Connection.
</Info>

## Tablist

Die Einträge für die Tablist stehen in der `config.yml`. Der `name` wird mit dem Server verglichen, auf dem der Spieler ist.

```yaml config.yml
tablist:
  - name: Lobby
    layout:
      - header: '<green>Lobby'
        footer: '<gray>Du bist auf <server_name>'
      - header: '<yellow>SimpleCloud'
        footer: '<gray><online_players> Spieler online'
    update-time: 100

  - name: global
    layout:
      - header: '<color:#0ea5e9>SimpleCloud v3'
        footer: '<gray>Netzwerk'
    update-time: 20
```

Der Proxy verwendet den ersten passenden Eintrag:

1. Genauer Servername, zum Beispiel `Lobby-1`
2. Anfang des Servernamens, zum Beispiel `Lobby` für `Lobby-1`
3. `*`
4. `global`

Hat ein Eintrag mehrere Layouts, wechseln sie alle `update-time` Ticks. Mit `update-time: 0` wird immer das erste Layout angezeigt.

## Spielerzahl

Die Spielerzahl enthält alle Proxys der aktuellen Proxygruppe. Du kannst weitere Gruppen und persistente Server hinzufügen oder alle Spieler im Netzwerk anzeigen.

```yaml config.yml
player-count:
  enabled: true
  network: false
  additional-groups:
    - BedrockProxy
  additional-persistent-servers:
    - EventProxy
  update-time: 20
```

| Einstellung | Beschreibung |
| ----------- | ------------ |
| `network` | `true` zeigt alle Online Spieler im Netzwerk |
| `additional-groups` | Gruppen, deren Spieler dazugezählt werden |
| `additional-persistent-servers` | Persistente Server, deren Spieler dazugezählt werden |
| `update-time` | Intervall in Ticks. `0` zählt nur einmal beim Start |

<Note>
  Pings von dem Rechner, auf dem der Proxy läuft, zeigen die echte Spielerzahl und keinen Hover Text. Teste die Spielerzahl deshalb von einem anderen Rechner.
</Note>

## Kick Verhalten

```yaml config.yml
show-kick-reason: false
```

Mit `true` wird ein Spieler, der von einem Backend Server gekickt wird, mit dem Kick Grund vom Netzwerk getrennt, statt auf einen Fallback Server geschickt zu werden.

## Platzhalter

| Platzhalter | Wo | Beschreibung |
| ----------- | -- | ------------ |
| `<online_players>` | Überall | Online Spieler |
| `<max_players>` | Überall | Maximale Spieler nach dem gewählten Slot Typ |
| `<date>` | Überall | Aktuelles Datum |
| `<time>` | Überall | Aktuelle Uhrzeit |
| `<date:'pattern'>` | Überall | Datum und Uhrzeit in deinem eigenen Format, zum Beispiel `<date:'HH:mm'>` |
| `<env:NAME>` | Überall | Wert einer Umgebungsvariable |
| `<env:NAME:default>` | Überall | Wert einer Umgebungsvariable mit Fallback |
| `<server_name>` | Tablist | Server, auf dem der Spieler ist |
| `<ping>` | Tablist | Ping des Spielers in der passenden Farbe |

<Warning>
  Zeige mit `<env:NAME>` keine Passwörter, Tokens oder andere geheime Daten an. Die MOTD kann jeder sehen.
</Warning>

Die Datumsformate und Ping Farben kannst du in der `messages.yml` ändern.

Alle Texte verwenden [MiniMessage](https://docs.papermc.io/adventure/minimessage/). Alte Farbcodes wie `&a` werden nicht unterstützt.

## Befehle

| Befehl | Beschreibung |
| ------ | ------------ |
| `/scproxy` oder `/scproxy help` | Zeigt die Befehle, die du verwenden kannst |
| `/scproxy reload` | Lädt das Plugin neu |
| `/scproxy joinstate help` | Zeigt die Join State Befehle |
| `/scproxy joinstate list` | Zeigt alle Join States aus der `config.yml` |
| `/scproxy joinstate info` | Zeigt den Join State aller Gruppen und persistenten Server |
| `/scproxy joinstate info <group\|ps> <target> [id]` | Zeigt den Join State einer Gruppe, eines Servers oder eines persistenten Servers |
| `/scproxy joinstate set <group\|ps> <target> <joinstate> [id]` | Setzt den Join State einer Gruppe, eines Servers oder eines persistenten Servers |
| `/scproxy layout help` | Zeigt die Layout Befehle |
| `/scproxy layout info [group]` | Zeigt das Layout einer Gruppe, ohne Gruppe das `initial-layout` |
| `/scproxy layout set <group> <layout>` | Setzt das Layout einer Gruppe |

Die letzten beiden Berechtigungen kannst du in der `config.yml` ändern.

## Andere Plugins verwenden

Du musst nicht alle Funktionen nutzen. Schalte die aus, die ein anderes Plugin übernimmt:

| Funktion | So schaltest du sie aus |
| -------- | ----------------------- |
| MOTD | Setze `motd.enabled: false` in jedem Layout |
| Tablist | Setze `tablist: []` in der `config.yml` |
| Spielerzahl | Setze `player-count.enabled: false` in der `config.yml` |
| Join Beschränkungen | Setze alle Gruppen auf einen Join State mit leerem `permission.join`, zum Beispiel `public` |

Ein MOTD Plugin muss auf dem Proxy laufen, nicht auf einem Lobby Server.

## Fehlerbehebung

<AccordionGroup>
  <Accordion title="Das Plugin oder seine Dateien fehlen">
    Prüfe, ob Proxy Essentials und `simplecloud-api` im **Proxy** Template liegen und nicht in einem Lobby Template. Starte den Proxy danach neu und prüfe die Konsole.
  </Accordion>

  <Accordion title="Der Wartungsmodus ist aktiv, aber die MOTD ändert sich nicht">
    Prüfe, ob du den Join State auf der Proxygruppe gesetzt hast und nicht nur auf einer Backend Gruppe. Prüfe außerdem, ob das `forced-motd-layout` in `layout/` existiert und `motd.enabled: true` hat.
  </Accordion>

  <Accordion title="Eine Domain zeigt die normale MOTD">
    Prüfe, ob der Spieler genau die Domain aus `domain` verwendet, ob `target` eine Gruppe oder ein persistenter Server ist und ob das Layout aus `rules` existiert.
  </Accordion>

  <Accordion title="Niemand kann joinen">
    Prüfe die Konsole. Wenn eine Gruppe einen Join State verwendet, der nicht in der `config.yml` steht, kann niemand joinen. Füge den Join State hinzu oder setze die Gruppe auf einen vorhandenen.
  </Accordion>

  <Accordion title="Farben werden als Text angezeigt">
    Ersetze alte Farbcodes wie `&a` durch MiniMessage Tags wie `<green>`.
  </Accordion>
</AccordionGroup>
