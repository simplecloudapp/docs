## Überblick

Das Server Connection Plugin ist das zentrale Routing-Plugin für SimpleCloud-Proxys. Es registriert verfügbare SimpleCloud-Server auf dem Proxy, entfernt sie beim Stoppen wieder, sendet Spieler zu passenden Join-Zielen und leitet Spieler bei Kicks oder Serverausfällen zu Fallback-Zielen weiter.

Außerdem kannst du Spielerbefehle wie `/lobby`, `/hub` oder `/leave` definieren, die Spieler zum am wenigsten belegten passenden Zielserver senden.

<Note>
  Server-Registrierung ist Teil von Server Connection. Du brauchst kein separates
  Registrierungs-Plugin für Proxy-Registrierung, externe Server, Join-Ziele oder
  Fallback-Routing.
</Note>

## Schnellstart

<Steps>
  <Step title="Plugin installieren">
    Lade das Plugin von [GitHub](https://github.com/simplecloudapp/server-connection-plugin/releases) herunter und lege es im `plugins/`-Ordner deines Proxy-Templates ab.
  </Step>

  <Step title="API-Plugin installieren">
    Stelle sicher, dass das `simplecloud-api` Plugin im selben Proxy-Template installiert ist. Server Connection nutzt es, um SimpleCloud-Server und Events zu lesen.
  </Step>

  <Step title="Konfiguration erzeugen">
    Starte den Proxy einmal, damit das Plugin `config.yml`, `commands.yml` und `messages.yml` erzeugt.
  </Step>

  <Step title="Routing konfigurieren">
    Bearbeite die erzeugten Dateien, um registrierte Servernamen, Connections, Join-Ziele, Fallback-Ziele und Spielerbefehle festzulegen.

    <Check>
      Nach einem Reload oder Neustart sollte `/connection reload` alle Server-Connection-Konfigurationsdateien ohne Fehler neu laden.
    </Check>
  </Step>
</Steps>

## Erzeugte Dateien

| Datei | Zweck |
| ----- | ----- |
| `config.yml` | Registrierung, Address-Routen, Connections, Network-Join-Ziele und Fallbacks |
| `commands.yml` | Spielerbefehle wie `/lobby` und `/hub` |
| `messages.yml` | Kick-Nachrichten und `/connection reload`-Nachrichten |

## Server-Registrierung

Server-Registrierung ist der Teil von Server Connection, der Server auf dem Proxy sichtbar macht. Wenn sie aktiviert ist, hält das Plugin die Serverliste des Proxys über SimpleCloud-Events aktuell.

Beim Start leert das Plugin vorhandene Proxy-Servereinträge, registriert `additionalServers`, lädt aktuell verfügbare SimpleCloud-Game-Server und beobachtet Server-Events.

Nur Server mit Gruppentyp `SERVER` werden registriert. Server mit dem Blueprint-Configurator `standalone` werden übersprungen.

```yaml
version: 1

registration:
  enabled: true
  serverNamePattern: "<group>-<numerical_id>"
  persistentServerNamePattern: "<name>"
  ignoreServerGroupsAndPersistentServers: []
  additionalServers:
    - name: "external-lobby"
      address: "127.0.0.1"
      port: 25565
```

### Externen Server registrieren

Nutze `additionalServers` für Server, die auf dem Proxy sichtbar sein sollen, aber nicht von SimpleCloud verwaltet werden.

```yaml
registration:
  enabled: true
  additionalServers:
    - name: "external-lobby"
      address: "127.0.0.1"
      port: 25565
```

Externe Server können über `connections` wie andere registrierte Proxy-Server gefunden werden.

### Registrierungsplatzhalter

| Platzhalter | Beschreibung |
| ----------- | ------------ |
| `<group>` | Gruppenname für Gruppenserver |
| `<name>` | Name des Persistent Servers |
| `<numerical_id>` | Numerische ID eines Gruppenservers |
| `<id>` | Server-UUID |

Eigene Server-Properties sind ebenfalls als MiniMessage-Platzhalter verfügbar. Property-Namen werden kleingeschrieben und `-` wird durch `_` ersetzt.

## Connections

Eine Connection ist eine benannte Gruppe registrierter Server. Die Standardkonfiguration erstellt eine `lobby`-Connection, die registrierte Servernamen mit `lobby` am Anfang findet.

```yaml
connections:
  - name: "lobby"
    serverNameMatcher:
      operation: "STARTS_WITH"
      value: "lobby"
      negate: false
    rules: []
```

Regeln können eine Connection per Berechtigung oder Umgebungsvariable einschränken. Spieler mit `bypassPermission` überspringen die jeweilige Regel.

```yaml
connections:
  - name: "vip-lobby"
    serverNameMatcher:
      operation: "STARTS_WITH"
      value: "vip-lobby"
      negate: false
    rules:
      - type: "PERMISSION"
        name: "network.vip"
        value: "true"
        bypassPermission: "network.admin"
```

## Address-Routen

Address-Routen senden Spieler anhand des Hostnamens, mit dem sie dem Proxy beitreten, zu einer Connection. Das ist nützlich, wenn `play.example.com` und `events.example.com` in unterschiedliche Lobbys führen sollen.

```yaml
address:
  routes:
    - subdomain: "events.example.com"
      targetConnection: "event-lobby"
```

Wenn keine Address-Route passt, nutzt das Plugin `networkJoinTargets`.

## Network Join Targets

Network Join Targets entscheiden, wohin ein Spieler beim Beitritt zum Proxy gesendet wird. Höhere Prioritäten werden zuerst versucht.

```yaml
networkJoinTargets:
  enabled: true
  targetConnections:
    - name: "lobby"
      priority: 0
```

## Fallback-Ziele

Fallback-Ziele entscheiden, wohin ein Spieler nach einem Kick oder Server-Shutdown gesendet wird. Mit `from` kannst du ein Fallback-Ziel auf bestimmte Connections begrenzen.

```yaml
fallback:
  enabled: true
  targetConnections:
    - name: "lobby"
      priority: 0
      from: []
```

## Spielerbefehle

Spielerbefehle werden in `commands.yml` konfiguriert. Jeder Befehl zeigt auf ein oder mehrere fallback-artige Ziele und verbindet den Spieler mit dem am wenigsten belegten passenden Server.

```yaml
version: 1

commands:
  - name: "lobby"
    aliases:
      - "l"
      - "hub"
      - "quit"
      - "leave"
    permission: ""
    messages:
      alreadyConnected: "<color:#dc2626>You are already connected to this lobby!"
      noTargetConnectionFound: "<color:#dc2626>Couldn't find a target server!"
    targetConnections:
      - name: "lobby"
        priority: 0
        from: []
```

## Admin-Befehl

| Befehl | Berechtigung | Beschreibung |
| ------ | ------------ | ------------ |
| `/connection reload` | `simplecloud.connection.reload` | `config.yml`, `commands.yml` und `messages.yml` neu laden |

## Routing-Ablauf

1. Das Plugin sortiert Ziel-Connections nach Priorität.
2. Es überspringt Ziele, deren `from`-Filter nicht zum aktuellen Server des Spielers passt.
3. Es sucht die benannte Connection in `config.yml`.
4. Es prüft die Connection-Regeln.
5. Es sammelt registrierte Servernamen, die zum Matcher passen.
6. Es verbindet den Spieler mit dem am wenigsten belegten passenden Server.
7. Wenn kein Ziel funktioniert, wird die konfigurierte No-Target-Nachricht angezeigt oder der Spieler gekickt.

<Tip>
  Nutze eine Connection pro logischem Ziel, zum Beispiel `lobby`, `minigames`
  oder `vip-lobby`, und referenziere diese Namen in Join Targets, Fallbacks und
  Befehlen.
</Tip>
