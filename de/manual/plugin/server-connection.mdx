## Plugin installieren

<Steps>
  <Step title="Plugin installieren">
    Lade Server Connection von [GitHub](https://github.com/simplecloudapp/simplecloud-plugins/releases) oder [Modrinth](https://modrinth.com/organization/simplecloud) herunter und lege die JAR in den Ordner `plugins/` des Proxy Templates.
  </Step>

  <Step title="Lobby Server anpassen">
    Standardmäßig werden Spieler auf Server geschickt, deren Name mit `lobby` beginnt. Wenn deine Lobby Gruppe anders heißt, passe die Connection `lobby` in der `config.yml` an.
  </Step>

  <Step title="Plugin prüfen">
    Starte einen Proxy und joine. Wechsle danach auf einen anderen Server und führe `/lobby` aus.

    <Check>
      Du landest auf einem Lobby Server, und `/lobby` bringt dich zurück in eine Lobby.
    </Check>
  </Step>
</Steps>

Beim ersten Start erstellt Server Connection die Dateien `config.yml`, `commands.yml` und `messages.yml` in `plugins/simplecloud-connection/`. Damit deine Änderungen erhalten bleiben, kopiere den Ordner ins Proxy Template. Mehr dazu unter [Templates](/de/manual/setup/templates).

<Warning>
  Mit `registration.enabled: true` ersetzt Server Connection die Serverliste des Proxys durch deine SimpleCloud Server. Trage Server außerhalb von SimpleCloud in `registration.additional-servers` ein oder setze `registration.enabled` auf `false`, wenn ein anderes Plugin die Serverliste verwaltet.
</Warning>

## So funktioniert es

Alles basiert auf **Connections**. Eine Connection ist eine benannte Auswahl an Servern, zum Beispiel alle Server, die mit `lobby` beginnen. Connections verwendest du an vier Stellen:

| Stelle | Beschreibung |
| ------ | ------------ |
| `network-join-targets` | Wohin Spieler beim Betreten des Netzwerks kommen |
| `fallback` | Wohin Spieler kommen, wenn ihr Server stoppt oder sie kickt |
| `address.routes` | Wohin Spieler kommen, wenn sie mit einer bestimmten Domain joinen |
| `commands.yml` | Wohin Befehle wie `/lobby` Spieler schicken |

Innerhalb einer Connection kommt der Spieler auf den Server mit den wenigsten Spielern. Server, die gerade stoppen, werden übersprungen.

## config.yml

```yaml config.yml
version: 2

registration:
  enabled: true
  server-name-pattern: '<group>-<numerical_id>'
  persistent-server-name-pattern: '<name>'
  ignore-server-groups-and-persistent-servers: []
  additional-servers: []

address:
  routes: []

connections:
  - name: lobby
    server-name-matcher:
      operation: STARTS_WITH
      value: lobby
      negate: false
    rules: []

network-join-targets:
  enabled: true
  target-connections:
    - name: lobby
      priority: 0

fallback:
  enabled: true
  target-connections:
    - name: lobby
      priority: 0
      from: []
```

### Server registrieren

| Einstellung | Beschreibung |
| ----------- | ------------ |
| `enabled` | Registriert SimpleCloud Server auf dem Proxy |
| `server-name-pattern` | Name von Gruppenservern auf dem Proxy. Platzhalter: `<group>`, `<numerical_id>`, `<id>`, `<name>` |
| `persistent-server-name-pattern` | Name von persistenten Servern auf dem Proxy |
| `ignore-server-groups-and-persistent-servers` | Gruppen und persistente Server, die nicht registriert werden |
| `additional-servers` | Server außerhalb von SimpleCloud |

In den Namen kannst du auch Server Properties verwenden. Aus einer Property wie `display-name` wird `<display_name>`.

```yaml config.yml
registration:
  additional-servers:
    - name: build
      address: 127.0.0.1
      port: 25565
```

### Connections

```yaml config.yml
connections:
  - name: lobby
    server-name-matcher:
      operation: STARTS_WITH
      value: lobby
      negate: false
    rules: []
```

| Operation | Passt, wenn der Servername | Beispiel |
| --------- | -------------------------- | -------- |
| `STARTS_WITH` | mit dem Wert beginnt | `lobby` |
| `ENDS_WITH` | mit dem Wert endet | `-1` |
| `CONTAINS` | den Wert enthält | `hub` |
| `EQUALS` | genau dem Wert entspricht | `lobby-1` |
| `REGEX` | komplett zu einer Java Regex passt | `lobby-\d+` |
| `PATTERN` | komplett zu einer Java Regex passt, wie `REGEX` | `lobby-\d+` |
| `GREATER_THAN` | eine Zahl größer als der Wert ist | `5` |

`STARTS_WITH`, `ENDS_WITH`, `CONTAINS` und `EQUALS` ignorieren Groß und Kleinschreibung. Mit `negate: true` drehst du das Ergebnis um, zum Beispiel für alle Server, die **nicht** mit `lobby` beginnen.

### Regeln

Regeln legen fest, ob ein Spieler eine Connection verwenden darf. Wenn eine Regel nicht erfüllt ist, wird die Connection übersprungen und die nächste versucht.

**Berechtigung**

```yaml config.yml
rules:
  - type: PERMISSION
    name: server.join.vip
    value: 'true'
    bypass-permission: rank.admin
```

Mit `value: 'true'` braucht der Spieler die Berechtigung. Mit `value: 'false'` darf er sie nicht haben.

**Umgebungsvariable**

```yaml config.yml
rules:
  - type: ENV
    name: SERVER_STATE
    value: maintenance
    operation: EQUALS
    negate: true
    bypass-permission: rank.admin
```

Vergleicht eine Umgebungsvariable des Proxys mit `value`. Du kannst jede Operation aus der Tabelle oben verwenden.

Spieler mit der `bypass-permission` überspringen die Regel. Regeln gelten überall: beim Join, beim Fallback, bei Subdomain Routen und bei Befehlen.

### Join und Fallback

`network-join-targets` legt fest, wohin Spieler beim Join kommen. `fallback` legt fest, wohin sie kommen, wenn ihr Server stoppt oder sie kickt.

```yaml config.yml
network-join-targets:
  enabled: true
  target-connections:
    - name: vip-lobby
      priority: 10
    - name: lobby
      priority: 0

fallback:
  enabled: true
  target-connections:
    - name: lobby
      priority: 0
      from: []
```

- Die Connection mit der höchsten `priority` wird zuerst versucht.
- Hat sie keinen freien Server oder ist eine Regel nicht erfüllt, wird die nächste Connection versucht.
- `from` verwendet den Fallback nur, wenn der Spieler von einer dieser **Connections** kommt. Lass die Liste leer, um alle Server zu erlauben.
- Wird kein Server gefunden, wird der Spieler vom Netzwerk getrennt.

### Subdomain Routen

Schicke Spieler je nach Domain, mit der sie joinen, zu einer Connection:

```yaml config.yml
address:
  routes:
    - subdomain: 'play.example.com'
      target-connection: lobby
    - subdomain: 'smp.example.com'
      target-connection: smp

connections:
  - name: lobby
    server-name-matcher:
      operation: STARTS_WITH
      value: lobby
      negate: false
    rules: []

  - name: smp
    server-name-matcher:
      operation: EQUALS
      value: smp
      negate: false
    rules: []
```

Spieler, die mit `smp.example.com` joinen, kommen auf den Server `smp`. Alle anderen verwenden `network-join-targets`.

- Verwende die vollständige Domain, zum Beispiel `smp.example.com`. Wildcards wie `*.example.com` werden nicht unterstützt.
- `target-connection` ist der Name einer Connection, nicht eines Servers.
- Hat die Route keinen freien Server oder ist eine Regel nicht erfüllt, wird `network-join-targets` verwendet.
- Lass jede Domain mit einem `A`, `AAAA` oder `CNAME` Eintrag auf deinen Proxy zeigen. Wenn der Proxy nicht den Port `25565` verwendet, brauchst du zusätzlich einen `SRV` Eintrag.

## commands.yml

Erstelle Befehle, die Spieler zu einer Connection schicken:

```yaml commands.yml
version: 2

commands:
  - name: lobby
    aliases:
      - l
      - hub
      - quit
      - leave
    permission: ''
    target-connections:
      - name: lobby
        priority: 0
        from: []
    messages:
      already-connected: '<color:#dc2626>You are already connected to this lobby!'
      no-target-connection-found: "<color:#dc2626>Couldn't find a target server!"
```

| Einstellung | Beschreibung |
| ----------- | ------------ |
| `name` | Name des Befehls |
| `aliases` | Weitere Namen für den Befehl |
| `permission` | Berechtigung für den Befehl. Leer lassen, damit alle ihn verwenden dürfen |
| `target-connections` | Connections, zu denen der Befehl schickt, mit `priority` und `from` wie bei `fallback` |
| `messages` | Nachricht, wenn der Spieler schon auf dem Ziel ist oder kein Server gefunden wird |

## Fehlerbehebung

<AccordionGroup>
  <Accordion title="Spieler kommen auf keinen Server">
    Prüfe, ob `network-join-targets.enabled` auf `true` steht und die Connection zu mindestens einem laufenden Server passt. Standardmäßig muss der Name mit `lobby` beginnen. Die Konsole warnt dich, wenn eine Connection verwendet, aber nicht definiert wird.
  </Accordion>

  <Accordion title="Ein Server außerhalb von SimpleCloud fehlt">
    Trage ihn in `registration.additional-servers` ein.
  </Accordion>

  <Accordion title="Eine Subdomain Route funktioniert nicht">
    Verwende die vollständige Domain in `subdomain`, lass die Domain auf den Proxy zeigen und prüfe, ob `target-connection` eine vorhandene Connection mit einem laufenden Server ist. Prüfe auch die Regeln der Connection.
  </Accordion>

  <Accordion title="Nach einem Neustart von SimpleCloud fehlen Server">
    Server Connection lädt alle Server neu, sobald SimpleCloud wieder erreichbar ist. Wenn danach noch Server fehlen, prüfe die Konsole des Proxys.
  </Accordion>
</AccordionGroup>
