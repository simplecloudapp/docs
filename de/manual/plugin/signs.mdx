## Unterstützte Software

| Servertyp | Unterstützung |
| --------- | ------------- |
| Paper und Forks | Ja |
| Spigot | Nein |

<Warning>
  Schildregistrierungen und ihre Welt müssen zusammenbleiben. Am einfachsten betreibst du das Plugin auf einer persistenten Lobby.

  Für eine temporäre Servergruppe konfigurierst du die Schilder auf einem persistenten Staging-Server. Stoppe ihn sauber und kopiere anschließend die Welt und `plugins/simplecloud-signs/locations/` ins Gruppen-Template. Kopiere keine laufende Welt ins Template.
</Warning>

## Plugin installieren

<Steps>
  <Step title="Server-Plugins installieren">
    Lade Signs von [GitHub](https://github.com/simplecloudapp/sign-plugin/releases) herunter und lege die JAR-Datei im Ordner `plugins/` des Paper-Server-Templates ab. Die Standard-Templates enthalten `simplecloud-api` bereits. Füge es bei einem eigenen Template über die Einstellung **Plugins** des Ziels oder über die CLI hinzu.
  </Step>

  <Step title="Layouts erzeugen">
    Starte einen passenden Server. Das Plugin legt seine Standardlayouts unter `plugins/simplecloud-signs/layouts/` an.
  </Step>

  <Step title="Schild registrieren">
    Platziere ein Schild, sieh es direkt an und führe einen dieser Befehle aus:

    ```text
    /sign add group Lobby
    /sign add persistent MainLobby
    ```

    Verwende den ersten Befehl für eine Servergruppe und den zweiten für einen persistenten Server.
  </Step>

  <Step title="Schild testen">
    Warte, bis sich der Text aktualisiert, und klicke auf das Schild. Ein Gruppenschild verbindet den Spieler mit dem Server, der diesem Schild gerade zugewiesen ist. Ein Schild für einen persistenten Server verbindet ihn, sobald dieser verfügbar ist.
  </Step>
</Steps>

## Befehle

Der Befehl ist als `/simplecloudsign`, `/simplecloudsigns`, `/scsigns`, `/scsign`, `/cloudsigns`, `/cloudsign`, `/signs` und `/sign` verfügbar.

| Befehl | Beschreibung |
| ------ | ------------ |
| `/sign help` | Hilfe anzeigen |
| `/sign list [page] [group]` | Registrierte Schilder auflisten, optional nach Ziel gefiltert |
| `/sign add group <group>` | Das anvisierte Schild für eine Servergruppe registrieren |
| `/sign add persistent <persistent-server>` | Das anvisierte Schild für einen persistenten Server registrieren |
| `/sign remove` | Das anvisierte Schild entfernen |
| `/sign remove <target>` | Alle Schilder einer registrierten Gruppe oder eines persistenten Servers entfernen |

<Note>
  Du musst den Schildblock ansehen, den du hinzufügen oder entfernen möchtest. Der Befehl prüft bis zu acht Blöcke weit.
</Note>

## Berechtigungen

| Berechtigung | Beschreibung |
| ------------ | ------------ |
| `simplecloud.command.signs` | Basisbefehl verwenden |
| `simplecloud.command.signs.list` | Registrierte Schilder auflisten |
| `simplecloud.command.signs.add` | Schilder registrieren |
| `simplecloud.command.signs.remove` | Anvisiertes Schild entfernen |
| `simplecloud.command.signs.remove.group` | Alle Schilder eines Ziels entfernen |

## Layouts

Layouts bestimmen, was ein Schild für einen Serverstatus anzeigt. Das Plugin enthält Layouts für `STARTING`, `OFFLINE`, `MAINTENANCE`, `FULL`, `EMPTY` und `ONLINE`. Starte den Server nach einer Layoutänderung neu, da das Plugin die Dateien beim Start liest.

```yaml
name: "online_default"
rule: "ONLINE"
priority: 9
behind-block: "LIME_CONCRETE"
frame-update-interval: 1250

frames:
  - lines:
      - "<color:#22c55e>⚡</color>"
      - "<group>-<numerical-id>"
      - "<player-count>/<max-players>"
      - "<color:#22c55e><b>ONLINE</b></color>"
```

| Feld | Beschreibung |
| ---- | ------------ |
| `name` | Eindeutiger Layoutname |
| `rule` | Eingebaute Regel, die entscheidet, wann das Layout gilt |
| `priority` | Höhere Prioritäten gewinnen, wenn mehrere Layouts passen |
| `type` | Optionaler Zieltyp: `ALL`, `GROUP` oder `PERSISTENT` |
| `matcher` | Optionale Namensfilter für dieses Layout |
| `serverName` | Optionaler Registrierungsname auf dem Proxy; Standard ist `%server-name%` |
| `behind-block` | Optionales Blockmaterial hinter einem gerichteten Schild |
| `frame-update-interval` | Animationsintervall in Millisekunden |
| `frames` | Ein oder mehrere vierzeilige Schild-Frames |

## Platzhalter

Verwende MiniMessage-Platzhalter in Layout-Zeilen.

| Platzhalter | Beschreibung |
| ----------- | ------------ |
| `<server-name>` | Name des Gruppenservers oder persistenten Servers |
| `<group>` | Gruppenname für Gruppenserver |
| `<numerical-id>` | Numerische ID für Gruppenserver |
| `<persistent-server>` | Name des persistenten Servers |
| `<server-id>` | Server-UUID |
| `<host>` | Serverhost-ID |
| `<ip>` | Server-IP-Adresse |
| `<port>` | Server-Port |
| `<min-memory>` | Minimaler Arbeitsspeicher in MB |
| `<max-memory>` | Maximaler Arbeitsspeicher in MB |
| `<max-players>` | Maximale Spielerzahl |
| `<player-count>` | Aktuelle Spielerzahl |
| `<state>` | Serverstatus |
| `<property:name>` | Eigene Servereigenschaft `name` |
| `<property:name:default>` | Eigene Servereigenschaft mit Ersatzwert |
| `<player_name>` | Spielername bei einer spielerspezifischen Aktualisierung |
| `<player_sender>` | Aktueller Server des Spielers, falls verfügbar |

## Muster für Servernamen

Das Feld `serverName` unterstützt diese Ersetzungen:

| Token | Beschreibung |
| ----- | ------------ |
| `%server-name%` | Standardname des Gruppenservers oder persistenten Servers |
| `%group%` | Gruppenname |
| `%numerical-id%` | Numerische ID |
| `%persistent-server%` | Name des persistenten Servers |

## Fehlerbehebung

<AccordionGroup>
  <Accordion title="Der Befehl findet das Schild nicht">
    Sieh das Schild direkt an und stelle dich höchstens acht Blöcke entfernt hin, bevor du den Befehl ausführst.
  </Accordion>

  <Accordion title="Das Schild bleibt offline">
    Prüfe, ob das Ziel existiert. Ein Gruppenschild benötigt außerdem einen geeigneten laufenden Server. Ein persistenter Server muss aktiv und auf dem Proxy registriert sein.
  </Accordion>

  <Accordion title="Eine Layoutänderung erscheint nicht">
    Starte den Server nach der Änderung neu. Das Plugin liest Layoutdateien beim Start.
  </Accordion>
</AccordionGroup>
